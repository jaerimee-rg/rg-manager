# 학부모 — 홈 화면에 추가 안내 팝업

> **상태: 구현 완료** (2026-10-11, 브랜치 `feat/parent-a2hs-prompt`).
> 아래는 구현 전에 세운 계획이며, 구현은 이 계획대로 했다. 바뀐 점과 검증 결과는 §8 에 적는다.

## 1. 요청

> 학부모 플랫폼에서 홈 화면에 아직 추가하지 않은 경우에 홈 화면에 추가 팝업을 띄워 줄 수 있어?
> 그리고 **다시 보지 않기** 버튼을 넣어서, 체크하면 보여 주지 말아 줘.

## 2. 가능한가 — 결론

**가능하다.** 단, 웹이 할 수 있는 일에는 한계가 있어 기기마다 방법이 다르다.

| 기기 · 브라우저 | 웹이 할 수 있는 것 | 팝업이 하는 일 |
|---|---|---|
| 안드로이드 크롬 · 삼성 인터넷 · 엣지 | 브라우저가 `beforeinstallprompt` 이벤트를 주면 **버튼 한 번으로 설치 창**을 띄울 수 있다 | **[홈 화면에 추가]** 버튼 → 브라우저의 설치 창 |
| 〃 (이벤트가 안 온 경우) | 크롬은 서비스 워커에 fetch 핸들러가 있어야 자동 설치 창 조건을 채운다 — 이 앱의 `sw.js` 는 알림만 다뤄서 없을 수 있다 | 메뉴(⋮ / ≡) → **홈 화면에 추가 / 앱 설치** 순서를 그림처럼 안내 |
| 아이폰 · 아이패드 (사파리, iOS 크롬 등) | **코드로 설치 창을 띄울 방법이 없다** (애플이 막아 둠) | 공유 버튼(□↑) → **홈 화면에 추가** → 추가 순서를 안내 |
| 카카오톡 안의 브라우저 | 웹뷰라 홈 화면에 추가 자체가 안 된다 | **[브라우저로 열기]** (`kakaotalk://web/openExternal`) → 열린 브라우저에서 다시 이 팝업이 뜬다 |
| 그 밖의 앱 안 브라우저 (네이버 · 인스타그램 …) | 추가도, 바깥 브라우저로 여는 표준 방법도 없다 | 띄우지 않는다 |
| PC | 설치는 되지만 "홈 화면" 이 아니다 | 띄우지 않는다 |

### "이미 추가했는지" 는 어떻게 아나

웹은 "이 사람이 홈 화면에 추가해 뒀는지" 를 **직접 물어볼 수 없다.** 그래서 신호 세 개를 합친다.

1. **지금 홈 화면 아이콘으로 열렸다** — `display-mode: standalone` 또는 `navigator.standalone` (iOS).
   이때는 당연히 안 띄운다.
2. **이 브라우저가 "설치됐다" 고 알려 줬다** — `appinstalled` 이벤트 (안드로이드 크롬은 메뉴로 설치해도 온다).
3. **이 기기에서 홈 화면 아이콘으로 열린 적이 있다** — 1번일 때 기록을 남긴다.
   안드로이드는 홈 화면 앱과 크롬 탭이 저장소를 같이 써서, 나중에 크롬 탭으로 들어와도 안 띄운다.

2·3번은 `localStorage` 의 `homeScreenPrompt.installed` 하나로 남긴다.
아이폰은 홈 화면 앱과 사파리의 저장소가 **분리**돼 있어 3번이 사파리에 전해지지 않는다.
그래서 아이폰에서 추가해 놓고 사파리로 다시 들어오면 팝업이 또 뜰 수 있다. 이럴 때 쓰라고 **다시 보지 않기**가 있다.

## 3. 요구사항

| ID | 요구사항 |
|---|---|
| A2HS-1 | 학부모가 학부모 화면(일정 · 사진 · 추천 상품 · 내 정보 · 이벤트 상세)에 들어오면, 위 표의 "띄우는" 환경이고 아직 추가하지 않았으면 안내 팝업을 띄운다 |
| A2HS-2 | 온보딩(아이 등록) · 초대 링크 화면에서는 띄우지 않는다 — 가입부터 끝내게 한다 |
| A2HS-3 | 팝업에 **다시 보지 않기** 체크박스가 있다. 체크한 채로 닫으면(닫기 · X · 바깥 누르기 · Esc · 버튼) 이 기기에서는 다시 띄우지 않는다 |
| A2HS-4 | 체크하지 않고 닫으면 **이번에 연 동안은** 다시 띄우지 않고, 다음에 앱을 새로 열면 다시 띄운다 (탭 단위 `sessionStorage`) |
| A2HS-5 | 안드로이드에서 설치 창을 띄울 수 있으면 [홈 화면에 추가] 버튼 한 번으로 설치 창을 연다. 설치하면 팝업을 닫고 다시는 띄우지 않는다 |
| A2HS-6 | 아이폰 · 이벤트가 없는 안드로이드는 순서를 글로 안내한다 |
| A2HS-7 | 카카오톡 안에서는 [브라우저로 열기] 를 준다 |
| A2HS-8 | 관리자가 학부모 계정으로 들어와 본 화면(FR-388)에서는 띄우지 않는다 |
| A2HS-9 | 선생님 · 관리자 화면에는 영향이 없다 (크롬의 기본 설치 안내도 그대로 둔다) |

**범위 밖**: 내 정보에 "홈 화면에 추가" 메뉴를 두어 다시 볼 수 있게 하는 것, 오프라인 캐시(서비스 워커 fetch),
선생님용 안내. 필요하면 다음에 한다.

## 4. 설계

### 4.1 파일

| 파일 | 내용 |
|---|---|
| `client/src/utils/homeScreen.js` (신규) | 순수 로직 — 환경 판별 `homeScreenEnvironment(nav, win)`, 저장소 읽기/쓰기, `shouldOfferHomeScreen()`, `beforeinstallprompt` · `appinstalled` 를 받아 두는 `listenForInstallPrompt()` |
| `client/src/components/parent/HomeScreenPrompt.jsx` (신규) | 바텀시트(`Modal`) — 환경별 본문 + 다시 보지 않기 + 닫기 / 홈 화면에 추가 / 브라우저로 열기 |
| `client/src/components/parent/ParentApp.jsx` | 온보딩 · 초대 화면이 아닐 때 `<HomeScreenPrompt />` 를 그린다 |
| `client/src/index.jsx` | 앱이 뜨기 전에 `listenForInstallPrompt()` — 이벤트는 페이지가 열리자마자 한 번만 오므로 React 보다 먼저 받아 둔다 |
| `client/src/components/ui/Icon.jsx` | `share`(□↑) · `plusSquare` 아이콘 추가 — 아이폰 안내에 그 버튼 모양을 그대로 보여 준다 |
| `client/src/styles/ui.css` | `.ui-a2hs` 블록 (단계 목록 · 아이콘 칩) |
| `client/src/utils/pushNotifications.js` | `isIos` · `isStandalone` · `openExternalUrl` 을 그대로 재사용 (중복 구현 안 함) |

서버 · DB 변경 **없음** — 기록은 기기(브라우저) 단위라 `localStorage` 로 충분하다. 계정 단위로 묶으면
"아빠 폰에서 다시 보지 않기" 가 "엄마 폰" 까지 막아 버린다. 이 팝업은 그 기기에 관한 안내라 기기 단위가 맞다.

### 4.2 환경 판별 — `homeScreenEnvironment(nav, win)`

순서대로 처음 맞는 것:

| 결과 | 조건 | 팝업 |
|---|---|---|
| `installed` | `isStandalone()` | 안 띄움 (+ 설치 기록) |
| `kakaotalk` | UA 에 `KAKAOTALK` | 브라우저로 열기 |
| `in-app` | 안드로이드 웹뷰(`; wv)`) 이거나, iOS 인데 UA 에 `Safari/` 가 없음(WKWebView 앱 — 네이버 · 인스타그램 …) | 안 띄움 |
| `ios` | `isIos()` (아이패드가 맥으로 소개해도) | 공유 → 홈 화면에 추가 안내 |
| `android` | UA 에 `Android` | 설치 버튼 또는 메뉴 안내 |
| `other` | 그 밖(PC) | 안 띄움 |

### 4.3 저장소 키

| 저장소 | 키 | 값 | 뜻 |
|---|---|---|---|
| `localStorage` | `homeScreenPrompt.hidden` | `'1'` | 다시 보지 않기 |
| `localStorage` | `homeScreenPrompt.installed` | `'1'` | 설치됨 (appinstalled · 홈 화면으로 열린 적 있음 · 설치 창에서 수락) |
| `sessionStorage` | `homeScreenPrompt.shown` | `'1'` | 이번 탭에서 이미 보여 줌 |

모든 읽기/쓰기는 `try/catch` — 사파리 개인정보 보호 모드처럼 저장소가 막혀도 앱이 깨지지 않는다
(막혔으면 다시 보지 않기를 지킬 수 없으니 그때는 한 번 보여 준다).

### 4.4 `beforeinstallprompt`

- `index.jsx` 에서 앱이 뜨기 전에 리스너를 단다. 이벤트를 받으면 보관해 두고, **로그인한 사용자가 학부모일 때만**
  `preventDefault()` 로 크롬의 기본 미니 안내줄을 막는다 (학부모는 우리 팝업이 대신하고, 선생님은 크롬 기본 안내를 그대로 본다 — A2HS-9).
- 팝업은 보관된 이벤트가 생기거나 사라질 때 알림을 받아(구독) 본문을 버튼형 ↔ 안내형으로 바꾼다.
  팝업이 이미 메뉴 안내로 떠 있다가 이벤트가 오면 그 자리에서 버튼이 생긴다.
- `prompt()` 는 이벤트 하나에 한 번만 된다. 부르고 나면 보관한 이벤트를 버린다.
  `userChoice.outcome === 'accepted'` 면 설치 기록을 남기고 닫는다. `'dismissed'` 면 팝업만 닫는다(다시 보지 않기 체크 상태는 지킨다).

### 4.5 화면

`Modal mode="sheet" size="sm"` — 휴대폰에서는 아래에서 올라오는 시트, 아이패드 폭에서는 가운데 창.
앱이 그려진 뒤 **1.2초** 있다가 띄운다 (첫 화면을 먼저 보여 주고, 그 사이에 설치 이벤트가 올 시간도 준다).
그때 다른 창(`[role="dialog"]` — 공유 링크로 연 사진 뷰어 · 시트 · 메뉴)이 떠 있으면 겹치지 않고 1.2초마다 다시 보며 닫힐 때까지 기다린다.

```
┌──────────────────────────────────────┐
│ 홈 화면에 추가해 두세요            ✕ │
│ 아이콘 한 번이면 일정·사진이 바로 열려요 │
│                                      │
│  (환경별 본문 — 아래)                │
│                                      │
│  ☐ 다시 보지 않기                    │
├──────────────────────────────────────┤
│        [ 홈 화면에 추가 ]  (있을 때)  │
│        [ 닫기 ]                      │
└──────────────────────────────────────┘
```

- **ios**: ① 공유 버튼 [□↑] 을 누르세요 (아이폰은 화면 아래, 아이패드는 위 · 안 보이면 ⋯ 안) ② **홈 화면에 추가** [⊞] 를 고르고
  ③ 오른쪽 위 **추가**. 덧붙임: "아이폰은 홈 화면에 추가한 앱에서만 새 일정·사진 알림을 받을 수 있어요."
- **android + 이벤트 있음**: 한 줄 설명 + 주 버튼 **[홈 화면에 추가]**.
- **android + 이벤트 없음**: ① 브라우저 메뉴 **⋮** (삼성 인터넷은 아래 **≡**) ② **홈 화면에 추가** 또는 **앱 설치** ③ **추가 / 설치**.
- **kakaotalk**: "카카오톡 안에서는 홈 화면에 추가할 수 없어요" + 주 버튼 **[브라우저로 열기]**
  (열린 브라우저에서 카카오 로그인을 한 번 더 하면 그곳에서 이 안내가 다시 떠요).

## 6. 테스트 계획

**단위 (jest)** — `utils/__tests__/homeScreen.test.js`, `components/parent/__tests__/HomeScreenPrompt.test.js`

- 환경 판별: 안드로이드 크롬 · 삼성 인터넷 · 카카오톡(안드/iOS) · 네이버 앱(iOS) · 안드 웹뷰 · 아이폰 사파리 · iOS 크롬 · 아이패드(맥 UA+터치) · PC · standalone
- `shouldOffer`: 숨김 · 설치됨 · 이번 탭에서 이미 봄 · 관리자 대리 접속 · 저장소가 던질 때
- 컴포넌트: 1.2초 뒤에 뜬다 / 체크하고 닫으면 `hidden` 저장 / 체크 안 하고 닫으면 `hidden` 없음 + `shown` 저장 /
  설치 이벤트가 있으면 버튼 → `prompt()` → accepted 면 `installed` 저장 · 닫힘 / 팝업이 뜬 뒤 이벤트가 와도 버튼이 생긴다 /
  카카오톡은 `kakaotalk://web/openExternal?url=…` 링크 / 띄우지 않는 환경은 아무것도 안 그린다

**e2e (Playwright, parent 프로젝트 — 휴대폰 폭)** — 기존 parent 테스트는 PC UA 라 팝업이 안 떠 영향이 없다.
새 스펙만 `test.use({ userAgent })` 로 휴대폰 UA 를 쓴다. 이미 아이가 등록된 `parentMulti` 세션을 쓴다.

- 안드로이드 UA: 팝업이 뜨고 메뉴 안내가 보인다 → 다시 보지 않기 체크 → 닫기 → 새로고침 · 새 탭에서도 안 뜬다
- 안드로이드 UA: 체크 없이 닫기 → 같은 탭 새로고침엔 안 뜨고, 새 탭(새 세션)에선 다시 뜬다
- 설치 이벤트를 흉내 내 넣으면 [홈 화면에 추가] → `prompt()` 가 불리고, 수락하면 다시는 안 뜬다
- 아이폰 UA: 공유 → 홈 화면에 추가 안내 / 홈 화면 앱(`navigator.standalone`)으로 열면 안 뜬다
- 카카오톡 UA: [브라우저로 열기] 가 `kakaotalk://web/openExternal` 주소를 가리킨다
- 온보딩 화면에서는 안 뜬다

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 안드로이드 크롬이 `beforeinstallprompt` 를 안 줄 수 있다 (fetch 핸들러 조건) | 메뉴 안내가 기본 경로라 기능은 그대로 된다. 빈 fetch 핸들러를 넣는 꼼수는 모든 요청을 서비스 워커로 돌게 해 느려지므로 하지 않는다 |
| 아이폰은 홈 화면 앱에서 저장소가 분리돼 추가 후 사파리에서 다시 뜰 수 있다 | 다시 보지 않기로 끈다. 문구에 "이미 추가했다면 다시 보지 않기를 체크해 주세요" |
| 팝업이 공유 링크로 연 이벤트 상세를 가린다 | 시트 하나 · 1.2초 뒤 · 닫으면 그 탭에선 다시 안 뜬다 |
| e2e 기존 테스트가 팝업에 막힐 수 있다 | parent 프로젝트는 PC UA 라 `other` 로 판별돼 안 뜬다. 새 스펙만 휴대폰 UA |

## 8. 구현하며 바뀐 점 · 검증

계획대로 구현했다. 계획과 다른 점은 셋이다.

- **설치 이벤트는 역할과 상관없이 보관한다** — `preventDefault()` 만 학부모일 때 한다. 카카오 로그인 콜백 직후처럼
  사용자 정보가 저장되기 전에 이벤트가 와도, 학부모 화면이 뜬 뒤 팝업이 그 이벤트로 설치 창을 열 수 있게 하려는 것이다.
  선생님 화면은 이 이벤트를 쓰는 곳이 없어 달라지는 것이 없다.
- 아이폰 안내의 공유 버튼 위치 — 아이패드 사파리는 공유 버튼이 **위**에 있어 "아이폰은 화면 아래, 아이패드는 위" 로 고쳤다.

- **다른 창이 떠 있으면 기다린다** (PR 리뷰에서 추가) — 공유 링크 `?open=` 으로 사진 뷰어(z-index 240)가 바로 열린 경우 팝업이
  뷰어 뒤에 숨고, 두 창을 닫는 순서에 따라 `Modal` 의 스크롤 잠금(`body.style.overflow`)이 풀리지 않을 수 있었다.
  `isAnotherOverlayOpen()` 이 참이면 1.2초마다 다시 본다.

아래 버튼 줄의 [닫기] 는 제목 줄 X 와 이름이 같다(업로드 시트와 같은 관례). 테스트는 버튼 줄(`.ui-overlay__footer`) 안에서 찾는다.
