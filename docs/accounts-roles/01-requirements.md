# 계정 · 역할 · 초대 체계 — 요구사항

> 상태: **초안 — 2026-08-30** · 관련: [README](./README.md), [02-data-model-api.md](./02-data-model-api.md), [03-implementation-plan.md](./03-implementation-plan.md)
> FR 번호는 기존 문서와 겹치지 않게 **FR-300 부터** 쓴다 (학부모 포털 FR-01~99, 사진 공유 FR-200~295).

## 1. 배경 및 목적

### 1.1 지금의 문제

| # | 사실 (코드 확인) | 문제 |
|---|---|---|
| 1 | `authController.kakaoCallback`: `state` 가 없으면 **누구나** 카카오 로그인만으로 `role='user'`(선생님) 계정이 생긴다 | **아무나 선생님이 된다.** 링크를 아는 사람이 아니라 카카오 계정만 있으면 된다 |
| 2 | `users."kakaoId"` UNIQUE — 카카오 계정 하나 = 계정 하나 | **선생님이면서 자기 아이의 학부모**인 사람은 카카오 계정이 두 개 필요하다. 실제로 선생님 계정이 학부모 초대 링크를 타면 `409 이미 선생님 계정으로 사용 중` 으로 거절된다 |
| 3 | 관리자는 관리자 > 사용자에서 **역할 편집**(선생님 → 관리자)으로만 생긴다 | 승격되는 순간 그 사람의 "선생님 계정" 이 사라진다(같은 행의 역할이 바뀐다) |
| 4 | 다른 역할 화면을 보려면 **로그아웃 → 다른 카카오 계정** 뿐 | 관리자·선생님·학부모를 겸하는 사람이 매번 계정을 갈아탄다 |
| 5 | `parent_accounts (userId PK, teacherId NOT NULL)` — 학부모 1명 = 선생님 1명 | 형제가 다른 선생님에게 다니거나 학원을 옮기면 **계정을 새로 만들어야** 한다 |

### 1.2 목적

1. 로그인은 지금처럼 **하나**(`/login`, 카카오 버튼)로 둔다.
2. **같은 카카오 계정으로 관리자·선생님·학부모 계정을 각각** 갖고, 로그인 뒤 **역할 전환**으로 화면을 오간다.
3. 가입은 **초대로만** — **선생님은 관리자**가, **학부모는 선생님**이 초대한다. 초대 없는 카카오 로그인은 계정을 만들지 않는다.
4. **학부모는 여러 선생님과 연결**될 수 있고, **연결된 선생님의 이벤트만** 보고 신청한다.
5. 기존 선생님·학부모·관리자의 **데이터와 화면은 그대로** 동작한다.

### 1.3 조직 구조 (2026-08-30 확정)

- **관리자 1명**(서비스 운영자). 선생님을 초대하고 전체 데이터를 본다.
- **선생님 여러 명.** 각자 자기 학생·수업·출석·이벤트·앨범을 소유한다.
- **학부모**는 자기를 초대한 **선생님(들)** 에게 연결된다. **한 학부모 ↔ 여러 선생님** 가능.
- **자녀**(`parent_children`)는 **선생님 1명의 학생**(`students`)에 대응한다. 같은 아이가 두 선생님에게 다니면 자녀 행이 둘이다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 관리자 | `users.role = 'admin'`. **1명**. 선생님 초대·전체 조회·사용자 관리 |
| 선생님 | `users.role = 'user'`. 학생·수업·출석·이벤트·앨범을 소유 |
| 학부모 | `users.role = 'parent'`. 카카오로만 로그인. 연결된 선생님(들)의 일정·사진을 본다 |
| 카카오 계정 / 사람 | 카카오 회원번호(`users."kakaoId"`). 이 문서에서 "같은 사람" = 같은 `kakaoId` |
| 계정 | `users` 행 하나. **역할당 최대 1개** → 한 사람 최대 3개 |
| 활성 역할 | 브라우저에 저장된 JWT 의 `role`. 브라우저당 하나 |
| 역할 전환 | 활성 역할을 같은 카카오 계정의 다른 역할 계정으로 바꾸는 것(카카오 재인증 없음) |
| **선생님 초대** | 관리자가 발급하는 **일회용** 토큰(`teacher_invites`). `https://<도메인>/teacher-invite/<token>` |
| **학부모 초대** | 선생님이 발급하는 **재사용** 링크(`parent_invites`, 현행). `https://<도메인>/invite/<token>` |
| **선생님 연결** | 학부모 ↔ 선생님 한 쌍(`parent_teachers` 행). 이것이 있어야 그 선생님의 이벤트를 보고 신청한다 |
| 자녀 | `parent_children` 행. 학부모·선생님·(연결되면) 학생을 가리킨다 |
| 마지막 역할 | 이 브라우저에서 마지막으로 로그인·전환한 역할(localStorage). 로그인 힌트 |
| `state` | 카카오 OAuth 가 인가 요청에 실어 콜백에 돌려주는 문자열 |

## 3. 범위

### 3.1 포함

- `users` 의 `("kakaoId", role)` 복합 UNIQUE — 한 사람, 여러 역할
- 카카오 콜백의 계정 선택(마지막 역할 → 우선순위)과 **초대 없는 가입 차단**
- **선생님 초대**: 관리자 발급·회수·사용 이력, 초대 랜딩 화면, 초대로만 선생님 계정 생성
- **학부모 다중 선생님**: `parent_teachers` 다대다, 일정·사진·자녀·신청의 선생님 스코프 확장, 학부모 화면의 선생님 필터, 선생님 추가
- 역할 조회·전환 API 와 전환 메뉴(선생님 헤더 · 관리자 사이드바 · 학부모 내 정보 · 설정)
- 역할 계정 만들기: 선생님(초대 필요, 관리자는 예외), 학부모(초대 필요)
- 관리자 화면: 선생님 초대 관리, 역할 배지 3종, [관리자 계정 추가], 학부모 목록의 선생님 연결 관리
- 단위·컴포넌트·e2e 테스트, `CLAUDE.md` 갱신

### 3.2 제외 (후속 과제)

- 역할별 로그인 페이지 분리 — **폐기** (§10)
- 로그인 직후 역할 선택 화면 (§9 Q-8)
- 관리자 여러 명·승인 큐 (관리자 1명 전제)
- 브라우저 하나에서 두 역할 동시 로그인(탭별 세션)
- 이벤트마다 학부모를 따로 지정하는 **이벤트 단위 초대** — 링크 단위로 확정(§5.7)
- 학부모가 스스로 선생님 연결을 끊기 (§9 Q-5)
- 기존 선생님 계정의 초대 체계 소급 정비 — 운영 DB 는 2026-08-30 정리 완료(README 확정 #2), 코드 변경은 없음
- `/api/auth/signup`(비밀번호 가입 API) 정리

## 4. 사용자 스토리

**관리자**

- US-300 아무나 카카오로 선생님이 되면 안 된다. 내가 **초대 링크를 만들어 준 사람만** 선생님으로 가입되면 좋겠다.
- US-301 초대 링크를 만들고, 누가 썼는지 보고, 안 쓴 링크는 **회수**하고 싶다.
- US-302 나는 관리자이면서 수업도 한다. 관리자 화면에서 **선생님 계정으로 전환**하고 싶다.
- US-303 사용자 목록에서 누가 관리자·선생님·학부모인지, 같은 사람의 계정이 몇 개인지 보고 싶다.

**선생님**

- US-310 내 초대 링크를 받은 학부모만 내 일정·사진을 보고 신청할 수 있으면 좋겠다.
- US-311 내 아이도 여기 다닌다. **같은 카카오 계정**으로 학부모 계정을 만들어 헤더 메뉴로 학부모 화면에 가고 싶다.
- US-312 학부모 화면에서 **선생님 화면으로** 카카오 로그인 없이 돌아오고 싶다.

**학부모**

- US-320 큰애는 김 선생님, 작은애는 박 선생님에게 다닌다. **계정 하나로 두 선생님의 일정**을 보고 각각 신청하고 싶다.
- US-321 새 선생님의 초대 링크를 받으면 **기존 계정에 선생님을 추가**하고 싶다. 계정을 또 만들고 싶지 않다.
- US-322 일정·사진이 섞이면 헷갈린다. **선생님별로 걸러 보고** 싶다.
- US-323 아이를 등록할 때 **어느 선생님의 학생인지** 고르고 싶다.
- US-324 나는 학부모이자 선생님이다. 내 정보에서 **선생님 화면으로** 갈 수 있으면 좋겠다.

**모두**

- US-330 다음에 `/login` 으로 들어오면 **마지막에 쓰던 역할**로 바로 들어가면 좋겠다.
- US-331 초대 없이 로그인하면 계정이 생기는 대신 **무엇을 해야 하는지** 알려줬으면 한다.

## 5. 기능 요구사항

### 5.1 로그인 (FR-300~309)

| ID | 요구사항 |
|---|---|
| FR-300 | 로그인 페이지는 **`/login` 하나**, 카카오 버튼 하나. 화면·문구는 현행 유지(안내 문구만 §FR-306 에 맞게 조정) |
| FR-301 | 인가 URL 요청(`GET /api/auth/kakao`)에 브라우저가 기억하는 **마지막 역할**을 `prefer` 힌트로 붙인다. 힌트는 `state` 로 콜백에 돌아온다 |
| FR-302 | 콜백은 그 `kakaoId` 의 **모든 계정**을 조회해 하나를 고른다: ① `prefer` 역할 계정이 있으면 그것 ② 없으면 **관리자 > 선생님 > 학부모** 순 첫 번째 |
| FR-303 | **초대가 없고 계정도 하나도 없으면 계정을 만들지 않는다.** `403 { outcome: 'needsInvite' }` 로 안내 화면을 띄운다 (현행처럼 선생님 계정을 자동 생성하지 않는다) |
| FR-304 | 콜백 응답에 그 카카오 계정의 **계정 목록**(`accounts: [{ role, username }]`)을 함께 내려 화면이 다른 역할 계정 유무를 알 수 있게 한다 |
| FR-305 | 로그인 후 이동: 관리자 `/admin`, 선생님 `/`(신규면 `/register-name`), 학부모 온보딩/일정(현행) |
| FR-306 | 초대 없음 안내 화면(`/login?outcome=needsInvite`): "가입에는 초대가 필요해요 — **선생님**은 관리자에게, **학부모**는 다니는 학원 선생님에게 초대 링크를 요청해 주세요." + [다른 카카오 계정으로 로그인] |
| FR-307 | 하위 호환: `state` 가 비면 힌트 없음, 디코딩이 안 되는 비어 있지 않은 `state` 는 **옛 학부모 초대 토큰**으로 해석 |
| FR-308 | 카카오 scope 는 현행(`talk_message`) 유지 — 로그인 시점에는 역할을 모르므로 선생님·관리자에게 필요한 권한을 항상 요청한다 |

### 5.2 같은 카카오 계정, 여러 역할 (FR-310~319)

| ID | 요구사항 |
|---|---|
| FR-310 | `users."kakaoId"` 단일 UNIQUE 를 **`("kakaoId", role)` 복합 UNIQUE** 로 바꾼다. 카카오 계정당 역할별 행 1개, 최대 3개 |
| FR-311 | 카카오 계정으로 사용자를 찾는 코드는 **역할을 함께** 보거나(`getByKakaoId(kakaoId, role)`) **목록**을 본다(`listByKakaoId(kakaoId)`). 역할 없이 한 행을 찾는 호출은 남기지 않는다 |
| FR-312 | 역할별 행의 `username` 이 겹치면 `이름_2`, `이름_3` … 접미사(현행 학부모 규칙). 새 행 기본 이름은 **현재 계정 이름**(전환 메뉴에서 생성) 또는 **카카오 닉네임**(초대 링크로 생성) |
| FR-313 | 역할별 행은 **서로 독립**. 한 행을 지워도 다른 역할 행은 남는다. 데이터 이전·알림 동의·카카오 토큰도 행 단위 |
| FR-314 | 카카오 토큰은 **관리자·선생님 행에** 저장(학부모 행은 NULL, 현행). 전환 메뉴로 선생님/관리자 행을 만들 때는 **현재 행의 토큰을 복사**해 알림 발송이 재로그인 없이 되게 한다 |
| FR-315 | 선생님(또는 관리자) 카카오 계정이 학부모 초대 링크를 타면 **학부모 행을 만든다**. 현행 409 거절은 없앤다 |

### 5.3 역할 전환 (FR-320~329)

| ID | 요구사항 |
|---|---|
| FR-320 | `GET /api/auth/roles` — 현재 토큰의 카카오 계정이 가진 **계정 목록**과 **만들 수 있는 역할**. 비밀번호 전용 계정(`kakaoId` 없음)은 목록 = 자기 자신 |
| FR-321 | `POST /api/auth/switch-role { role }` — 같은 `kakaoId` 의 그 역할 행이 있으면 **새 JWT + user**. 없으면 404. `kakaoId` 는 요청 본문이 아니라 **현재 토큰의 사용자 행**에서 읽는다 |
| FR-322 | 전환 메뉴 위치: **선생님** 헤더 우측 역할 메뉴(데스크톱 nav · 모바일 메뉴) + 설정 카드 / **관리자** 사이드바 하단(모바일 메뉴 포함) + 설정 카드 / **학부모** 내 정보 카드. 보유한 다른 역할은 "○○ 화면으로", 없는 역할은 "○○ 계정 만들기" |
| FR-323 | 보유한 다른 역할도, 만들 수 있는 역할도 없으면 메뉴를 **숨긴다** |
| FR-324 | 전환하면 토큰·사용자·마지막 역할을 **교체**하고 그 역할의 홈(`/admin` · `/` · `/parent/schedule`)으로 이동한다 |
| FR-325 | 전환은 **세션 교체**. 동시에 두 역할로 로그인되지 않으며 다른 탭도 다음 요청부터 새 역할로 동작한다 — 메뉴 도움말에 적는다 |
| FR-326 | 전환은 `logs` 에 `SWITCH_ROLE`(선생님 → 학부모)로 남는다 |
| FR-327 | 관리자 사이드바의 기존 **"메인으로 돌아가기"**(같은 관리자 계정으로 선생님 UI 보기)는 유지하고, 전환 항목은 그 위에 구분해 둔다 |
| FR-328 | 학부모 행으로 전환하면 `parent_accounts.lastLoginAt` 을 갱신한다 |

### 5.4 역할 계정 만들기 (FR-330~339)

| ID | 요구사항 |
|---|---|
| FR-330 | `POST /api/auth/roles { role, invite? }` — 현재 카카오 계정에 그 역할 행을 만들고 **즉시 그 역할로 전환된 JWT** 를 돌려준다. `role` 은 `user`(선생님) 또는 `parent` 만 |
| FR-331 | **선생님 계정 만들기**: 이미 있으면 409. **유효한 선생님 초대 토큰이 필요**하다(FR-340~). 예외로 **현재 역할이 관리자면 토큰 없이** 만들 수 있다(관리자는 스스로에게 초대를 발급할 수 있으므로 같은 권한) |
| FR-332 | **학부모 계정 만들기**: 이미 있으면 → 계정을 만들지 않고 **선생님 연결만 추가**(FR-352). `invite`(학부모 초대 토큰)가 있으면 그 선생님에게 연결. 토큰이 없고 **현재 역할이 선생님이면 자기 학원 학부모**로 연결(`teacherId = 현재 id`), 그 외에는 400 `needsInvite` |
| FR-333 | 학부모 계정을 만든 뒤에는 자녀가 없으므로 `/parent/onboarding` 으로 간다(현행 `ParentApp` 가드) |
| FR-334 | 만들기 화면: 선생님이면 **[내 학원 학부모로 가입]** + **초대 링크 입력**, 그 외에는 초대 링크 입력만. 입력은 토큰 원문 또는 `https://…/invite/<token>` 전체를 받는다 |
| FR-335 | **관리자 계정**은 이 API 로 만들 수 없다(400). 관리자 > 사용자의 [관리자 계정 추가]로만(FR-382) |
| FR-336 | 만들기는 `logs` 에 `ADD_ROLE` 로 남는다 |

### 5.5 선생님 초대 (관리자) (FR-340~349)

| ID | 요구사항 |
|---|---|
| FR-340 | 선생님 계정은 **관리자가 발급한 일회용 초대 토큰**(`teacher_invites`)으로만 만들어진다. 초대 없이 카카오로 들어오면 계정이 생기지 않는다(FR-303) |
| FR-341 | 관리자 화면(`/admin/teachers`, 또는 관리자 > 사용자 상단 카드)에서 **[초대 링크 만들기]**: 메모(누구에게 주는지)와 만료일(기본 **14일**)을 넣어 발급. 링크 복사 버튼 제공 |
| FR-342 | 초대 목록: 메모 · 만든 시각 · 만료 · 상태(**대기 / 사용됨 / 만료 / 회수됨**) · 사용한 계정 이름. **[회수]** 로 미사용 토큰을 즉시 무효화 |
| FR-343 | 초대는 **1회 사용**. 사용되면 `usedByUserId`·`usedAt` 이 기록되고 다시 쓸 수 없다 |
| FR-344 | 초대 랜딩 `/teacher-invite/:token`(비로그인 공개): 유효하면 "관리자가 **선생님** 계정을 초대했어요" + [카카오로 시작하기], 무효·만료·사용됨이면 "유효하지 않은 초대 링크" |
| FR-345 | 랜딩의 카카오 버튼은 `GET /api/auth/kakao?tinvite=<token>` 으로 시작한다. 콜백에서 토큰이 여전히 유효해야 계정이 만들어진다(그 사이 회수될 수 있다) |
| FR-346 | **이미 선생님 계정이 있는 카카오 계정**이 선생님 초대를 타면 계정을 만들지 않고 **그 선생님 계정으로 로그인**한다. 토큰은 **소비하지 않는다**(관리자가 다시 쓸 수 있게) |
| FR-347 | 발급·회수·사용은 `logs` 에 `CREATE_TEACHER_INVITE` / `REVOKE_TEACHER_INVITE` / `KAKAO_LOGIN`(가입) 으로 남는다 |
| FR-348 | 발급·조회·회수는 **관리자만**(`requireRole('admin')`). 랜딩 확인(`GET /api/teacher-invite/:token`)만 공개이고 **관리자 이름 외 내부 정보를 내려보내지 않는다** |
| FR-349 | **기존 선생님 계정은 그대로 로그인된다**(계정이 있으면 초대 불필요). 초대 필수는 앞으로의 신규 가입에만 적용된다. 단 운영 DB 는 2026-08-30 에 **이재림 선생님만 남기고 정리**됐다(README 확정 #2) |

### 5.6 학부모 ↔ 여러 선생님 (FR-350~369)

| ID | 요구사항 |
|---|---|
| FR-350 | 학부모 ↔ 선생님은 **다대다**(`parent_teachers`). 한 학부모가 여러 선생님과, 한 선생님이 여러 학부모와 연결된다 |
| FR-351 | 기존 `parent_accounts.teacherId` 의 연결을 `parent_teachers` 로 **백필**한다. 백필 뒤에도 컬럼은 **대표 선생님**(가장 먼저 연결된 선생님)으로 남겨 두고 새 코드는 읽지 않는다 |
| FR-352 | **이미 학부모 계정이 있는 사람**이 다른 선생님의 초대 링크를 타면 계정을 만들지 않고 **연결만 추가**한다. 이미 연결돼 있으면 아무 것도 바뀌지 않고 로그인만 된다 |
| FR-353 | 학부모 내 정보에 **연결된 선생님 목록**과 **[선생님 추가]**(초대 링크 붙여넣기). 자녀는 선생님 이름과 함께 보인다 |
| FR-354 | 자녀(`parent_children`)는 **선생님 1명에 속한다**(`teacherId`). 같은 아이가 두 선생님에게 다니면 자녀 행이 둘이다 |
| FR-355 | 자녀 등록(온보딩·추가)에서 선생님이 2명 이상이면 **선생님을 먼저 고른다**. 1명이면 자동 선택하고 화면에 이름만 보여준다 |
| FR-356 | 이름·생년월일 자동 매칭은 **고른 선생님의 학생 명단에서만** 한다(현행 규칙 그대로, 범위만 선생님 단위) |
| FR-357 | 일정(`/parent/schedule`)은 **연결된 선생님 전체**의 공개 이벤트를 날짜순으로 보여주고, 카드마다 **선생님 이름**을 표시한다. 선생님이 2명 이상이면 상단에 **선생님 필터 칩**(기본: 전체) |
| FR-358 | 사진(`/parent/photos`)도 같은 규칙 — 연결된 선생님 전체의 앨범, 앨범 카드에 선생님 이름, 2명 이상이면 필터 |
| FR-359 | 이벤트 상세·신청·취소는 **그 이벤트를 소유한 선생님과 연결돼 있어야** 한다. 연결이 없으면 404(존재를 알리지 않는다) |
| FR-360 | 선생님 화면의 **학부모 메뉴**(`/parents`)는 자기와 연결된 학부모만 본다(현행과 동일한 결과). 목록에는 그 학부모가 **다른 선생님과도 연결돼 있는지** 표시하지 않는다(개인정보) |

| FR-362 | **선생님 계정을 삭제**하면 그 선생님의 연결만 지운다. 연결이 하나도 남지 않은 학부모 계정은 함께 삭제한다(현행 `deleteByTeacher` 의 의도 유지) |
| FR-363 | `User.transferData`(선생님 계정 이전)는 `parent_teachers.teacherId` 와 `parent_children.teacherId` 도 함께 옮긴다. 받는 선생님에게 이미 같은 학부모 연결이 있으면 **중복 행을 지우고** 옮긴다 |
| FR-364 | 관리자 학부모 화면(`/admin/parents`)은 학부모별로 **연결된 선생님 전부**를 보여준다 |

### 5.7 이벤트 신청 자격 (FR-370~379)

> **2026-08-30 확정 — 링크 단위.** *"이벤트는 선생님이 등록한 학부모 아무나 신청 가능합니다."*
> 즉 **그 선생님의 초대 링크로 연결된 학부모라면 누구나** 그 선생님의 공개 이벤트를 보고 신청한다.
> 선생님이 이벤트마다 학부모 명단을 고르는 방식이 **아니다**. 참가 범위를 좁혀야 하면 이벤트의 `isPublished`(공개 여부)·`registrationOpen`(접수)·마감 시각으로 조절한다.

| ID | 요구사항 |
|---|---|
| FR-370 | 학부모가 이벤트를 **보려면**: ① 이벤트가 공개(`isPublished`) ② 이벤트 소유 선생님과 **연결**돼 있음 |
| FR-371 | 학부모가 이벤트에 **신청하려면** 추가로: ③ 자녀가 그 **선생님의 학생과 연결**(`status='linked'`)돼 있음 ④ 접수 조건 통과(`canRegister`: 휴관일 아님·접수 중·마감 전·시작 전 — 현행) |
| FR-372 | 연결되지 않은 선생님의 이벤트 id 로 상세·신청·취소를 호출하면 **404**(권한 오류가 아니라 없는 것으로 취급) |
| FR-373 | 자녀가 확인 대기(`pending`)면 지금처럼 "선생님이 아이 정보를 확인한 뒤에 신청할 수 있어요"(`child_pending`) |
| FR-374 | 신청 알림(`EVENT_REGISTRATION`)은 **그 이벤트를 소유한 선생님**에게 간다(현행은 학부모의 단일 소속 선생님에게 보냈다 — 다중 연결에서 잘못될 수 있어 이벤트 소유자로 바꾼다) |
| FR-375 | 앨범(사진) 접근 규칙은 현행 유지(확정된 자녀가 있는 이벤트만) + FR-370 의 연결 조건을 함께 만족해야 한다 |
| FR-376 | (참고) **이벤트 단위 초대**로 바꾸려면 `event_invitees(eventId, parentUserId)` 같은 표가 필요하고 선생님이 이벤트마다 명단을 골라야 한다. 지금 구조에서 비슷한 효과는 `isPublished`(공개 여부)·`registrationOpen`(접수)·마감 시각으로 낸다 |

## 8. 수용 기준

**가입 차단 · 선생님 초대**

- AC-300 초대 없이 새 카카오 계정으로 `/login` → 카카오 로그인하면 **`users` 행이 늘지 않고** "초대가 필요해요" 화면이 뜬다. JWT 가 저장되지 않는다.
- AC-301 관리자가 `/admin/teachers` 에서 초대를 만들고 그 링크로 카카오 로그인하면 `role='user'` 행이 생기고 `/register-name` → `/` 로 간다. 초대는 **사용됨**으로 바뀌고 같은 링크를 다시 열면 무효다.
- AC-302 관리자가 미사용 초대를 **회수**하면 그 링크로는 가입되지 않는다.
- AC-303 이미 선생님 계정이 있는 카카오가 선생님 초대를 타면 **로그인만** 되고 초대는 **대기 상태 그대로**다.
- AC-304 기존 선생님 계정들은 초대 없이도 계속 로그인된다.

**다중 역할 · 전환**

- AC-310 같은 카카오 계정이 선생님 계정을 가진 상태에서 학부모 초대 링크를 타면 409 가 아니라 **학부모 행이 생기고** 세션이 학부모로 바뀐다. 두 행의 데이터(학생·수업 / 자녀·연결)가 섞이지 않는다.
- AC-311 선생님 헤더 [학부모 화면으로] → 카카오 화면 없이 `/parent/schedule`, 내 정보 [선생님 화면으로] → `/`. 왕복 2회 정상.
- AC-312 관리자 사이드바 [선생님 계정 만들기](관리자는 토큰 불필요) → `/register-name` → `/`, 이후 헤더에 [관리자 화면으로] 가 보인다.
- AC-313 `POST /api/auth/switch-role` 은 다른 카카오 계정의 행으로 어떤 입력으로도 전환되지 않는다. `POST /api/auth/roles { role:'admin' }` 은 400.
- AC-314 계정이 둘인 사람이 학부모로 쓰다 로그아웃 후 `/login` 으로 오면 **학부모**로, localStorage 를 지운 브라우저에서는 **관리자 > 선생님 > 학부모** 우선순위로 로그인된다.

**학부모 다중 선생님**

- AC-320 학부모 A 가 선생님 T1 초대로 가입한 뒤 T2 의 초대 링크를 타면 **계정이 하나**로 유지되고 `parent_teachers` 에 행이 둘이 된다.
- AC-321 A 의 일정에 T1·T2 의 공개 이벤트가 날짜순으로 함께 보이고 카드에 선생님 이름이 있다. 필터 칩으로 T1 만 볼 수 있다.
- AC-322 A 가 자녀를 추가할 때 선생님을 고르고, 매칭은 **그 선생님의 학생 명단**에서만 이뤄진다. T1 자녀와 T2 자녀가 각각 만들어진다.
- AC-323 A 는 T2 이벤트에 T2 자녀로 신청할 수 있고, **T1 자녀로는 T2 이벤트에 신청할 수 없다**.
- AC-324 연결이 없는 선생님 T3 의 이벤트 id 로 상세·신청을 호출하면 404.
- AC-325 신청 알림은 **그 이벤트 소유 선생님**에게 간다(T2 이벤트면 T2 에게).
- AC-326 선생님이 학부모 연결을 해제하면 그 선생님 일정·사진이 A 의 화면에서 사라지고, **다른 선생님 것은 그대로**다. A 의 계정은 남는다.
- AC-327 선생님 계정을 삭제하면 그 연결만 사라지고, 남은 연결이 없는 학부모 계정만 함께 삭제된다.
- AC-328 기존 학부모(단일 선생님)는 백필 후 화면·신청·사진이 그대로 동작하고 필터 칩은 보이지 않는다.

**관리자 화면 · 공통**

- AC-330 관리자 > 사용자에서 학부모가 "학부모" 배지로 보이고 역할 셀렉트가 비활성이며, 같은 카카오 계정 행에 표시가 붙는다.
- AC-331 학부모 토큰으로 선생님 초대 API·`grant-admin` 을 부르면 403.
- AC-332 관리자가 자기 자신을 삭제하려 하면 400.
- AC-333 서버·클라이언트 `npm test` 전부 통과, Playwright(기존 + 신규 spec) 통과, `smoke:prod` 통과.

## 10. 폐기한 대안 — 역할별 로그인 페이지

2026-08-30 처음 요청은 `/admin/login` · `/teacher/login` · `/parent/login` 을 나누고 `state` 에 역할을 실어 콜백이 역할별로 가입·로그인하는 안이었다. 같은 날 **"로그인은 하나로, 로그인 후 전환"** 으로 바꿨다. 기록으로만 남긴다.

| 항목 | 분리 로그인안 | 채택안(이 문서) |
|---|---|---|
| 로그인 페이지 | 3개 + 역할 선택 화면 | **1개(현행)** |
| 역할 결정 시점 | 카카오 버튼을 누른 페이지 | 콜백이 계정 목록에서 선택 + **로그인 후 전환** |
| 관리자 가입 | 관리자 페이지에서 카카오 → 가입 요청 → 승인(`admin_signup_requests` 표) | 관리자 1명 전제 → **[관리자 계정 추가]** 만 |
| 선생님 가입 | 그대로 열어 둠 | **관리자 초대 필수**(이번 요구사항) |
| 학부모 | 선생님 1명에 소속 | **여러 선생님과 연결**(이번 요구사항) |
| 공통 | `("kakaoId", role)` 복합 UNIQUE, 역할별 행, 전환 API | 동일 |
