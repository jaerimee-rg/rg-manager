# 학부모 포털 — 요구사항

> 상태: **2차 초안 — 2026-08-23 답변 반영** (확장 범위의 결정 사항은 각 소절 "결정" 참조) · 관련: [README](./README.md), [02-data-model-api.md](./02-data-model-api.md)

## 1. 배경 및 목적

현재 서비스는 선생님(학원 계정)만 로그인해 학생·수업·출석·대회를 관리한다. 학부모는 로그인 없는 FAQ 채팅 링크로만
접점이 있다. 대회·이벤트·휴관일 안내와 참가 신청은 카톡방에서 수기로 받고 있어 누락·중복이 생긴다.

이 기능의 목적:

1. 학부모가 **앱 설치나 별도 회원가입 없이** 초대 링크 + 카카오로 바로 계정을 만든다.
2. 학부모는 로그인하면 **일정**에서 선생님이 올린 대회·이벤트·휴관일을 **올해 남은 순서대로 카드로** 보고, **자기 아이 이름으로 신청·취소**한다.
3. 선생님은 기존 **대회 관리**가 확장된 **이벤트 관리**에서 이벤트를 등록하고, 누가 무엇을 신청했는지 본다.
4. 학부모 포털은 이후 사진 공유·게시판·채팅 등으로 **메뉴를 늘릴 수 있는 골격**이어야 한다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 선생님 | 기존 `users.role = 'user'` 계정. 학생·수업·대회를 소유한다. 문서에서 "관리자" 라 쓰면 선생님을 뜻한다 |
| 시스템 관리자 | `users.role = 'admin'`. `/admin/*` 전체 조회 |
| 학부모 | 새 역할 `users.role = 'parent'`. 카카오로만 로그인하며 선생님 1명에게 속한다 |
| 자녀 | 학부모에게 연결된 `students` 행. 한 학부모에 여러 자녀, 한 자녀에 여러 학부모 가능 |
| 초대 링크 | 선생님이 발급하는 `https://<도메인>/invite/<token>`. 이 링크를 거친 카카오 로그인만 학부모 계정을 만든다 |
| 이벤트 | 일정에 올라가는 항목. 종류(`type`)는 **대회**(`competition`) / **스페셜 이벤트**(`special`, 예: 러닝·특강) / **휴관일**(`closure`) |
| 옵션 | 이벤트마다 선생님이 정하는 선택 항목 목록(예: 개인전·단체전·의상 대여 / 5km·10km). 학부모는 여러 개 고를 수 있다 |
| 신청 | 학부모가 자녀 1명에 대해 이벤트에 참가 의사를 남긴 것(`event_registrations`). 옵션 선택을 포함한다 |
| 확정 | (대회만) 선생님이 신청을 받아들여 기존 **참가 학생**(`competition_students`)으로 올린 상태 |

## 3. 범위

### 3.1 포함 (MVP)

- 학부모 역할, 초대 링크, 카카오 가입/로그인, 자녀 입력·자동 연결·선생님 수동 연결
- 학부모 포털 레이아웃 + **일정** 메뉴 (올해 남은 일정 카드 리스트 + 상세/신청/취소 — 달력 없음)
- 선생님 **이벤트 관리**: 대회 / 스페셜 이벤트 / 휴관일 등록·수정·삭제 (이름·일시·장소·옵션·설명·공개 여부·접수 설정)
- 선생님 **신청 현황**: 이벤트별 신청·취소 목록, 대회는 **확정 → 참가 학생 추가**
- 선생님 **학부모 메뉴**(별도 메뉴): 초대 링크 복사·재발급, 가입한 학부모·자녀·연결 상태, **학부모별 / 학생별** 두 방향에서 학부모↔학생 연결·해제·추가
- 기존 `competitions` 데이터를 이벤트로 **백필**해 이벤트 목록·학부모 일정에 바로 보이게
- 학부모 JWT 의 선생님 API 접근 차단
- (선택) 학부모 신청·취소 시 선생님 카카오 알림

### 3.2 제외 (2차 이후 — §10 확장 요구사항에서 분석)

원본 메모의 나머지 항목은 MVP 에서 빼되, 이 문서 **§10** 에서 같은 수준으로 분석하고 단계를 제안한다.

- 대회 상세 정보 확장(종목·대회 사진·영상·의상·코멘트) → §10.1
- 비용(의상비 토글 — 선생님 화면만, 학부모 표시 없음) → §10.2
- 사진 공유(Google Drive 앨범 + Supabase/Vercel 얼굴 인식 필터) → §10.3
- 게시판 → §10.4, 채팅(FAQ 통합) → §10.5
- 학부모에게 가는 알림(앱 내 알림만, 알림톡 없음) → §10.7
- 그 밖에 MVP 에서 뺀 것: 옵션별 가격·정원·대기, 초대 링크 만료·1회용·QR, 학부모 탈퇴 셀프서비스, 학부모가 자기 아이 정보를 직접 수정

## 4. 사용자 스토리

**학부모**

- US-01 카톡방에서 받은 링크를 누르면, 앱 설치 없이 카카오 버튼 하나로 가입하고 싶다.
- US-02 가입하면서 아이 이름과 생년월일만 넣으면 우리 아이로 바로 연결되면 좋겠다.
- US-03 앞으로 남은 대회·특강·휴관일이 날짜순으로 한눈에 보였으면 좋겠다. 지난 건 안 보여도 된다.
- US-04 대회 카드를 누르면 개인전/단체전 같은 옵션을 고르고 바로 신청하고, 사정이 생기면 내가 직접 취소하고 싶다.
- US-05 아이가 둘이면 각각 따로 신청하고 싶다.
- US-06 다음에 다시 들어올 때도 카카오 로그인 한 번이면 됐으면 좋겠다.

**선생님**

- US-10 초대 링크 하나를 복사해 단체 카톡방에 올리고 싶다.
- US-11 대회뿐 아니라 러닝·특강(스페셜 이벤트), 휴관일도 같은 화면에서 등록하고 싶다.
- US-12 이벤트에 옵션을 넣어 두고 학부모가 골라서 신청하게 하고 싶다.
- US-13 누가 무엇을 신청했는지, 누가 취소했는지 이벤트별로 보고 싶다.
- US-14 대회 신청이 들어오면 확인 후 기존 **참가 학생** 화면으로 넘겨 종목·참가비를 관리하고 싶다.
- US-15 아이 이름을 잘못 적어 연결이 안 된 학부모는 내가 목록에서 찾아 연결해 주고 싶다.
- US-16 학부모가 신청·취소하면 카톡으로 알림을 받고 싶다. (선택)

## 5. 기능 요구사항

우선순위: **필수** = MVP 출시 조건, **선택** = MVP 에 넣으면 좋으나 빠져도 출시 가능.

### 5.1 역할과 접근 제어

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | `users.role` 에 `parent` 를 추가한다. 학부모 계정은 `password` 없이 `kakaoId` 로만 식별된다(기존 `createWithKakao` 재사용, `password` 는 사용 불가 값). | 필수 |
| FR-02 | JWT 페이로드의 `role` 로 화면·API 를 분기한다. 기존 토큰 포맷(`{ id, username, role }`)은 바꾸지 않는다. | 필수 |
| FR-03 | **선생님·시스템 관리자용 API 전부**(`/api/students`, `/api/classes`, `/api/attendance`, `/api/competitions`, `/api/events`, `/api/faq*`, `/api/chat`(비공개 부분), `/api/auth/users` 등)는 `role = 'parent'` 토큰을 **403** 으로 거부한다. 현재 `verifyToken` 은 역할을 보지 않으므로 별도 미들웨어(`rejectParents` 또는 `requireRole('user','admin')`)를 라우터 단위로 적용한다. | 필수 |
| FR-04 | 학부모 전용 API 는 `/api/parent/*` 아래에 두고 `requireRole('parent')` 로 보호한다. 학부모는 **자기 선생님의 이벤트**와 **자기 자녀의 신청**만 읽고 쓸 수 있다(쿼리마다 `teacherId`/`parentUserId` 조건). | 필수 |
| FR-05 | 프론트: 학부모가 선생님 경로(`/`, `/students`, `/events` …)에 들어오면 `/parent/schedule` 로, 선생님이 `/parent/*` 에 들어오면 `/` 로 보낸다(`ProtectedRoute` 에 역할 조건 추가 + 새 `ParentRoute`). | 필수 |
| FR-06 | 시스템 관리자 화면(`/admin/users`)에서 학부모 계정은 역할 배지 "학부모" 와 소속 선생님을 표시한다. 역할 변경은 불가(학부모 ↔ 선생님 전환 없음). 상세 목록은 FR-88 의 `/admin/parents`. | 필수 |

### 5.2 초대 링크

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 선생님마다 초대 링크를 **1개** 갖는다. 처음 **학부모 메뉴**(또는 링크 복사 버튼)를 열 때 없으면 자동 생성한다. | 필수 |
| FR-11 | 토큰은 추측 불가능한 URL-safe 랜덤 문자열(22자 이상, 기존 `utils/publicId.js` 재사용). 링크 형식: `${APP_URL}/invite/<token>`. | 필수 |
| FR-12 | 학부모 메뉴 화면 **상단 우측의 링크 아이콘** 한 번으로 전체 링크를 클립보드에 복사하고 토스트로 알린다. FAQ 화면 공유 아이콘과 동일 컴포넌트·폴백(`execCommand`)을 쓴다. `aria-label` "학부모 초대 링크 복사". | 필수 |
| FR-13 | 학부모 메뉴 상단에 링크 전문, [복사], [재발급] 을 둔다. 재발급은 확인 후 기존 토큰을 즉시 무효화한다(이미 가입한 학부모는 영향 없음). | 필수 |
| FR-14 | 링크는 만료되지 않는다. (선택) 만료일을 설정할 수 있고, 만료·무효 토큰으로 접속하면 "유효하지 않은 초대 링크입니다. 선생님께 새 링크를 요청해 주세요." 를 보여준다. | 선택 |
| FR-15 | 링크 생성·재발급은 `logAction` 으로 감사 로그에 남긴다(`CREATE_PARENT_INVITE`, `REGENERATE_PARENT_INVITE`). | 필수 |

### 5.3 학부모 가입 · 로그인

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | `/invite/:token` 은 **비로그인** 공개 화면이다. 토큰이 유효하면 "○○ 선생님의 초대" 문구(선생님 `username`)와 **[카카오로 시작하기]** 버튼, 수집 항목 고지(카카오 닉네임·이메일, 아이 이름·생년월일이 선생님에게 제공됨)를 보여준다. 무효 토큰은 404 안내. | 필수 |
| FR-21 | [카카오로 시작하기] 는 기존 카카오 인가 URL 에 **`state` 로 초대 토큰**을 실어 보낸다(`GET /api/auth/kakao/url?invite=<token>`). 콜백 화면 `/oauth/kakao/callback` 은 `code` 와 함께 `state` 를 서버에 전달한다. | 필수 |
| FR-22 | 서버 콜백 처리: `state` 의 초대 토큰이 유효하면 (a) 해당 `kakaoId` 가 없을 때 **`role = 'parent'`** 로 계정을 만들고 `parent_accounts(userId, teacherId, inviteId)` 를 기록, (b) 이미 학부모 계정이면 로그인만, (c) **이미 선생님/관리자 계정인 카카오라면 학부모로 바꾸지 않고** "이미 선생님 계정으로 사용 중인 카카오 계정입니다" 로 거절한다. | 필수 |
| FR-23 | `state` 가 없는 일반 카카오 로그인(로그인 페이지 버튼)은 지금처럼 동작하되, 찾은 계정이 `parent` 면 학부모 토큰을 발급하고 `/parent/schedule` 로 보낸다. 즉 **로그인 페이지의 카카오 버튼 하나로 선생님도 학부모도 로그인**한다. 초대 링크는 최초 가입에만 필요하다. | 필수 |
| FR-24 | 콜백 응답에 `role` 과 `needsOnboarding`(학부모이고 자녀가 0명)을 포함한다. 클라이언트는 `needsOnboarding` 이면 `/parent/onboarding`, 아니면 `/parent/schedule` 로 이동한다. 기존 선생님 흐름(`isNewUser` → `/register-name`)은 그대로. | 필수 |
| FR-25 | 학부모 계정의 `username` 은 카카오 닉네임(중복 시 `닉네임_숫자`). 학부모는 `/register-name` 을 거치지 않는다. | 필수 |
| FR-26 | 학부모 계정에는 `talk_message` 동의·토큰 저장이 필요 없다(알림을 보내지 않음). 인가 요청 `scope` 는 기존과 같아도 되지만, 학부모 흐름에서는 `kakaoMessageConsent` 를 건드리지 않는다. | 필수 |
| FR-27 | 로그아웃·토큰 만료 처리는 기존 `AuthContext`/`tokenStorage` 를 그대로 쓴다. | 필수 |

### 5.4 자녀 등록 · 연결

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | `/parent/onboarding` 에서 **아이 이름(필수, 1~20자)** 과 **생년월일(필수, 날짜 선택)** 을 입력한다. [아이 추가] 로 여러 명을 입력할 수 있고, 최소 1명 입력 후 [시작하기]. 건너뛰기는 없다. | 필수 |
| FR-31 | 저장 시 서버는 초대한 선생님(`parent_accounts.teacherId`)의 `students` 중 **이름(공백 제거 후 일치) + 생년월일(`YYYY-MM-DD` 정규화 후 일치)** 인 학생을 찾는다. 정확히 1명이면 `status = 'linked'`, `studentId` 를 연결한다. | 필수 |
| FR-32 | 0명이거나 2명 이상(동명이인 동일 생일)이면 `status = 'pending'` 으로 입력값만 저장하고 가입은 완료한다. 학부모 화면에는 "선생님 확인 후 신청이 가능해요" 배지를 보여준다. | 필수 |
| FR-33 | 같은 학생에 다른 학부모가 이미 연결돼 있어도 연결을 허용한다(엄마·아빠). 같은 학부모가 같은 학생을 두 번 넣을 수는 없다. | 필수 |
| FR-34 | 학부모는 포털의 **내 정보**(`/parent/settings`)에서 자녀를 추가할 수 있다(같은 매칭 규칙). 이름·생년월일 수정/삭제는 MVP 에서 학부모가 직접 하지 않고 선생님에게 문의하도록 안내한다. | 필수 |

| FR-85 | 연결·해제는 모두 즉시 반영되고 요약 카드·필터 수가 갱신된다. 연결되면 그 학부모는 **바로 신청할 수 있다**(FR-53). 해제하면 자녀는 `pending` 으로 돌아가고 기존 신청은 유지된다(학생이 삭제된 경우만 CASCADE). | 필수 |

| FR-87 | 학생 관리 목록·상세에 "연결된 학부모 n명" 표시, 누르면 학부모 메뉴 학생별 보기로 이동. | 선택 |

## 8. 수용 기준 (출시 체크리스트)

- [ ] 선생님이 학부모 메뉴에서 링크를 복사해 보낸 주소로 학부모가 카카오 가입을 마치고 `/parent/schedule` 에 도착한다.
- [ ] 온보딩에 선생님 학생과 같은 이름·생년월일을 넣으면 연결됨, 다르면 확인 대기로 가입이 끝난다. 선생님은 **학부모 메뉴**에서 학부모별·학생별 어느 쪽에서든 대기 자녀를 연결할 수 있다.
- [ ] 선생님이 대회/스페셜/휴관일을 각각 등록하면 학부모 일정에 날짜순 카드로 보이고, 지난 이벤트와 비공개 이벤트는 보이지 않는다.
- [ ] 학부모가 대회 카드에서 옵션 2개를 골라 신청 → 선생님 신청 현황에 옵션과 함께 보인다 → 학부모가 취소 → 취소로 표시된다 → 다시 신청해도 중복 행이 생기지 않는다.
- [ ] 선생님이 대회 신청을 [확정] 하면 기존 참가 학생 관리 화면에 그 학생이 나타난다. 기존 대회 화면·학생별 대회·참가비 기능은 그대로 동작한다.
- [ ] 배포 후 기존 대회가 모두 선생님 이벤트 목록에 보이고, 올해 남은 대회는 학부모 일정에도 보인다(접수는 닫힌 상태).
- [ ] 학부모 토큰으로 `/api/students` 등을 호출하면 403. 다른 선생님의 이벤트 id 로 신청하면 404/403.
- [ ] 휴관일은 신청 영역이 없고, 진행 중인 기간 휴관일은 "진행 중" 으로 목록에 남아 있다.
- [ ] 마감 일시가 지난 이벤트는 신청·취소 버튼 대신 "접수 마감" 이 보인다.
- [ ] 서버·클라이언트 단위 테스트와 e2e 시나리오가 통과한다.

### 10.1 대회 상세 정보 확장 — 옵션(종목 포함) · 대회 사진 · 영상 · 의상 · 코멘트

**메모 원문** (선생님 1) "대회 일정 등록 (날짜, 이름, 종목, 대회 사진, 영상, 의상, 커멘트) -> 설정"

**결정 (2026-08-23 답변)**
- "-> 설정" = **대회 등록 시 선생님이 옵션을 설정**한다는 뜻. 별도 설정 메뉴가 아니다.
- **학부모에게는 "신청" 만 있다.** 선생님이 만들어 둔 옵션에 체크하고 신청/취소한다. 학부모 화면에 비용·의상 신청·입금 같은 추가 동작은 없다.
- **옵션은 선생님이 추가·삭제**한다(1차 FR-63~64 그대로). **종목도 별도 필드 없이 옵션으로** 다룬다 — 선생님이 "맨손·볼·후프…" 를 옵션으로 넣으면 된다.

**해석**

| 항목 | 해석 | 반영 |
|---|---|---|
| 날짜, 이름 | 이벤트 기본 정보 | 1차 (`events.date`, `title`) |
| 종목 | 학부모가 신청 때 체크하는 선택지 = **옵션** | 1차 옵션. 편의로 **[종목 6개 불러오기]** 프리셋 버튼만 추가 |
| 대회 사진 | 대회 **안내용** 이미지(포스터·요강). 대회 후 앨범은 §10.3 | 첨부(2차) |
| 영상 | 참고 영상 — **링크**(YouTube/Drive) | 첨부의 링크 항목(2차) |
| 의상 | **안내**(텍스트+사진). 신청·비용 아님 | 안내 블록(2차) |
| 커멘트 | 학부모 안내(공개) + 선생님 메모(비공개) | `description` (1차) + `privateNote` (2차) |

#### 10.3.1 앨범 보관·조회 — Google Drive

사진 바이트는 선생님이 올린 **Google Drive 폴더**에 둔다. 앱은 파일 id·썸네일 주소·태그·얼굴 벡터만 갖는다.

| 방식 | 흐름 | 비고 |
|---|---|---|
| **공개 폴더 + API 키** (MVP 권장) | 선생님이 폴더를 "링크가 있는 모든 사용자(보기)" 로 공유하고 URL 을 이벤트에 붙여넣는다. 서버는 **Google API 키만으로** `files.list`(폴더 안 이미지 목록)·`files.get?alt=media`(원본 다운로드) 를 호출한다. 썸네일은 `https://drive.google.com/thumbnail?id=<fileId>&sz=w400` | **OAuth 불필요**, 구현 가장 단순. 학부모가 전체 사진을 봐도 되므로(결정) 공개 폴더로 충분 |
| 선생님 OAuth (`drive.readonly`) | 비공개 폴더도 읽음 | 나중에 비공개가 필요해지면 추가(FR-12a). 토큰 저장은 카카오 토큰 패턴 |

#### 10.3.2 얼굴 인식 — Supabase 저장 + Vercel 인덱싱

**요청안**: 기준 얼굴 사진은 Supabase Storage, 인덱싱(얼굴 검출·임베딩)은 Vercel 서버리스.

| 구성 | 선택 | 이유 |
|---|---|---|
| 얼굴 이미지 저장 | Supabase Storage **비공개 버킷** `child-faces`, 경로 `{teacherId}/{studentId}/{uuid}.jpg`, 조회는 서명 URL(짧은 만료) | 아이 얼굴이라 공개 버킷(`faq-files`)과 분리. 업로드 유틸(`utils/storage.js`)은 재사용 |
| 얼굴 검출·임베딩 | **`@vladmandic/face-api`(face-api.js) + `@tensorflow/tfjs` WASM 백엔드**, Node 순수 JS. 모델(SSD MobileNet 검출 + 68 랜드마크 + 128차원 인식 ≈ 7MB)을 함수에 동봉 | 네이티브 바이너리가 없어 Vercel 에 그대로 올라간다. 외부 전송 없음, 건당 비용 없음 |
| 벡터 저장·매칭 | Postgres **pgvector** (`CREATE EXTENSION IF NOT EXISTS vector`, Supabase 기본 제공) — `vector(128)` 컬럼, 코사인/유클리드 거리 질의 | 새 자녀 얼굴이 등록되면 **SQL 한 번**으로 기존 앨범 전체와 대조된다(사진 재분석 불필요). 수백~수천 장 규모면 인덱스 없이도 충분 |
| 실행 단위 | 학부모 기준 사진: 업로드 직후 1장씩 즉시. 앨범: 선생님이 [얼굴 분석] 을 누르면 클라이언트가 **5장씩 반복 호출**(`POST /api/events/:id/photos/analyze?batch=5`), 진행률 표시. 서버는 한 호출에서 5장을 내려받아(2,000px 로 축소) 검출·임베딩 후 저장 | Vercel 함수 시간 제한(Hobby 10초·Pro 60초) 안에 들도록. 콜드스타트 때 모델 로딩 1~2초 |

**더 나은 방법으로 추천하는 것 (요청안과 함께 검토)**

1. **매칭을 pgvector 로** — 위 표의 선택. 요청안(Vercel 인덱싱)과 충돌하지 않고, "나중에 등록한 자녀도 기존 사진에서 바로 찾는다" 를 공짜로 얻는다. **적용 권장.**
2. **임베딩 계산을 브라우저에서** — 같은 face-api.js 모델을 선생님(앨범 분석)·학부모(기준 사진) 브라우저에서 돌리고 서버는 벡터만 받는다. Vercel 시간 제한·콜드스타트·다운로드 대역폭 문제가 사라지고 비용이 0 이지만, 선생님 휴대폰이 수백 장을 내려받아 처리해야 해서 느리고 탭을 닫으면 멈춘다. → **Vercel 인덱싱을 기본으로 하되, 배치 호출이 시간 제한에 자주 걸리면 앨범 분석만 브라우저로 옮기는 것을 예비안**으로 둔다.
3. 앨범도 Supabase 에 두는 안은 메모(Drive)에 맞지 않아 채택하지 않는다.

**파이프라인**

1. **자녀 얼굴 등록(학부모)**: 내 정보 > 자녀 > [얼굴 사진 등록] 1~3장. 클라이언트 리사이즈(≤1MB) → Supabase `child-faces` 업로드 → 서버가 얼굴 검출(정확히 1개 아니면 거절)·128차원 임베딩 → `child_face_profiles(descriptor)`. 간단 동의 체크("자녀 사진은 우리 아이 사진 찾기에만 사용됩니다").
2. **앨범 동기화(선생님)**: 폴더 URL 등록 → [새로고침] 으로 파일 목록 upsert(`event_photos`) → [얼굴 분석] 배치 호출 → 사진마다 검출된 **모든 얼굴의 임베딩과 위치**를 `photo_faces` 에 저장(얼굴 이미지는 저장하지 않음).
3. **매칭**: `photo_faces` ↔ `child_face_profiles` 거리 질의. 거리 ≤ 0.5(face-api 권장 임계값 0.6 보다 보수적) 이면 자동 태그(`photo_tags source='face'`), 0.5~0.6 은 "혹시 우리 아이?" 후보. 자녀 등록·분석 완료·[다시 매칭] 때마다 갱신.
4. **보정**: 선생님 수동 태그(우선), 학부모 [맞아요/아니에요] 확인(후보 → 태그 승격/제외).

### 10.5 채팅 — FAQ 기능과 통합 (확정)

**메모 원문** (학부모 5) "채팅" · **추가 지시** "대화의 경우 **FAQ 기능과 통합**"

**해석·결정** 학부모 채팅은 별도 시스템을 만들지 않고 **기존 FAQ 채팅**(AI 가 등록 FAQ 로 답하고, 선생님이 직접 답할 수 있으며, 대화 내역·presence·카카오 알림이 이미 있는 것) **위에 얹는다.** 학부모 포털의 "채팅" 메뉴는 로그인 학부모용 FAQ 채팅이고, 선생님은 지금의 **FAQ > 대화 내역** 한 화면에서 비로그인 문의와 학부모 대화를 함께 본다.

**현재 시스템** `/chat/:publicId` 공개 채팅(`visitorKey`·대화명 기반), `chat_sessions`/`chat_messages`, AI 자동 답변(채널·대화별 on/off), 선생님 presence, `FAQ_INQUIRY` 카카오 알림(메시지마다), 대화 내역 화면.

**요구사항**
