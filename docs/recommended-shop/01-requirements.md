# 선생님 추천 상품 (공개 상점) — 요구사항

> 상태: **구현 완료 — 2026-10-04** (브랜치 `feat/recommended-shop`) · 관련: [README](./README.md), [02-data-model-api.md](./02-data-model-api.md), [03-implementation-plan.md](./03-implementation-plan.md), 목업([선생님](./mockups/teacher-desktop.html) · [학부모](./mockups/parent-desktop.html))

## 1. 배경

선생님은 지금 학부모에게 "이 레오타드 괜찮아요", "후프는 이걸로 사세요" 같은 추천을 카카오톡으로 링크를 하나씩 보내 전한다.
링크가 대화에 묻혀 다시 찾기 어렵고, 학부모가 실제로 눌러 봤는지도 알 수 없다.

이 기능은 추천 상품을 **한 페이지에 쇼핑몰처럼** 모아 두고, 그 페이지 링크 하나만 공유하게 한다.
학부모는 **로그인하지 않아도** 볼 수 있고, 선생님은 **어떤 상품이 많이 클릭됐는지** 본다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| **상점** (`shops`) | 선생님 한 명의 추천 상품 페이지. 선생님당 1개. 이름·소개·공개 여부·공개 링크를 가진다 |
| **공개 링크** | `https://<앱>/shop/<publicId>`. `publicId` 는 128비트 난수(URL-safe 22자). 로그인 없이 열린다 |
| **상품** (`shop_products`) | 타이틀(필수) + 링크 주소·이미지·카테고리·가격(선택). 공개/숨김 상태와 표시 순서를 가진다 |
| **카테고리** (`shop_categories`) | 선생님이 관리하는 상품 종류 목록(발레복, 기구 …). 상품은 0~1개를 고른다 |
| **방문** | 학부모 브라우저가 공개 상점을 한 번 연 것(브라우저 세션당 1회로 센다) |
| **클릭** | 학부모가 링크가 있는 상품 카드를 눌러 상품 주소로 이동한 것 |
| **방문자** (`visitorKey`) | 브라우저마다 만드는 난수 키. 사람·기기를 특정하는 정보는 담지 않는다 |

## 3. 범위

### 3.1 포함

- 선생님: 상품 등록·수정·삭제·숨김·순서 변경, 이미지 업로드, 카테고리 관리, 상점 이름·소개·공개 여부 설정, 공개 링크 복사·미리 보기
- 학부모(비로그인): 공개 상점 열람, 카테고리 필터, 상품 링크 이동
- 통계: 기간별 상품 클릭 순위, 방문 수, 카테고리별 클릭

### 3.2 제외 (이번 범위 밖)

- 결제·장바구니·재고 — 이 앱은 **링크만** 건다. 구매는 상품 사이트에서 한다
- 학부모 포털(로그인 상태) 탭에 상점 노출 → Q-2
- 카카오톡 링크 미리보기(OG 태그 — 상점 이름·대표 이미지) → Q-5
- 상품 설명(본문)·여러 장 이미지·옵션 → 필요해지면 컬럼 추가로 확장
- 링크 깨짐 자동 점검, 가격 자동 수집(스크래핑)
- 시스템 관리자(`admin`) 화면의 상점 통계

## 4. 사용자 스토리

**선생님**
- T-1 휴대폰에서 상품 이름만 적고 바로 등록한다. 링크·사진은 나중에 채운다.
- T-2 쿠팡 상품 주소를 붙여 넣고, 갤러리에서 상품 사진을 골라 올리고, "기구" 카테고리와 가격 32,000원을 넣는다.
- T-3 [링크 복사] 로 상점 주소를 복사해 학부모 단톡방에 보낸다.
- T-4 시즌이 지난 상품은 지우지 않고 **숨긴다**(통계는 남는다).
- T-5 많이 추천하는 상품을 맨 위로 올린다.
- T-6 통계 탭에서 "최근 30일" 로 바꾸고, 어떤 상품이 가장 많이 눌렸는지·몇 명이 눌렀는지 본다.
- T-7 우리 학원에 맞게 카테고리를 "수구", "테이프·보호대" 로 추가한다.

**학부모**
- P-1 단톡방 링크를 누르면 로그인 없이 바로 상점이 열린다(카카오톡 인앱 브라우저 포함).
- P-2 "기구" 칩을 눌러 기구만 본다.
- P-3 상품 카드를 누르면 쇼핑몰 상품 페이지가 새 창으로 열리고, 뒤로 오면 상점이 그대로 있다.

## 5. 기능 요구사항

### 5.1 상점 · 공개 링크

| ID | 요구사항 |
|---|---|
| FR-400 | 선생님이 **추천 상품** 메뉴에 처음 들어오면 상점을 자동으로 만든다(`getOrCreate`, 동시 요청에도 선생님당 1개). 기본 이름은 `"{선생님 표시 이름} 선생님 추천 상품"`, 기본 카테고리 5개(FR-420)를 함께 만든다. |
| FR-401 | 공개 링크는 `/shop/<publicId>`. `publicId` 는 `utils/publicId.js:generatePublicId()`(128비트 난수)로 만들고 바뀌지 않는다. 화면 상단에 링크와 **[링크 복사]**(`copyToClipboard`), **[미리 보기]**(새 창)를 둔다. |
| FR-402 | 상점 설정: **이름**(1~40자, 필수), **소개**(0~300자, 줄바꿈 유지), **하단 안내문**(0~300자 — 제휴 링크 고지 등, Q-4), **공개 ON/OFF**(기본 ON). |
| FR-403 | 공개 OFF 이거나 없는 `publicId` 면 공개 페이지는 같은 화면 "지금은 볼 수 없는 페이지예요" 를 보여 준다(존재 여부를 구분해 알려 주지 않는다 — API 는 둘 다 404). |
| FR-404 | 공개 링크는 **로그인 여부·역할과 무관하게** 같은 화면이다. 선생님·학부모가 로그인한 상태로 열어도 앱 헤더·하단 탭 없이 공개 상점만 보인다(`/chat/:publicId` 와 같은 처리, 인증 확인을 기다리지 않는다). |

### 5.2 상품 등록 · 수정

| ID | 요구사항 |
|---|---|
| FR-410 | **[상품 등록]** → 등록 모달(모바일은 바텀시트). 입력 항목과 순서: **타이틀**(필수) → **연결할 주소** → **이미지** → **카테고리** → **가격**. 저장 후 목록 맨 위에 나타난다. |
| FR-411 | **타이틀**: 앞뒤 공백 제거 후 1~80자. 비어 있으면 저장 버튼 옆이 아니라 **필드 아래에** "타이틀을 입력해 주세요". 서버도 같은 규칙으로 400. |
| FR-412 | **연결할 주소**(선택): 앞뒤 공백 제거, 최대 2,000자. 스킴이 없고 도메인처럼 보이면(`coupang.com/…`) `https://` 를 붙인다. **`http:`·`https:` 만 허용** — `javascript:`, `data:` 등은 "웹 주소(https://…)를 입력해 주세요" 로 거절(서버·클라이언트 동일 함수 규칙, 02 §2). |
| FR-413 | **이미지**(선택): 파일 선택(모바일 갤러리·카메라). 허용 `jpg/jpeg/png/webp/gif`, **svg 거절**(FAQ 파일과 같은 이유). 브라우저가 긴 변 1,200px·JPEG 0.85 로 줄여 올리고(투명 배경은 흰색으로 채움), 디코드하지 못하면 원본을 그대로 보낸다. 서버 한도 4MB(초과 시 413 + 안내). 미리보기·**[이미지 빼기]** 를 제공한다. |
| FR-414 | 이미지는 상품을 먼저 저장한 뒤 `POST /api/shop/products/:id/image` 로 올린다(02 §3). 이미지 업로드가 실패해도 상품은 저장된 상태로 남고 "이미지를 올리지 못했어요. 수정에서 다시 시도해 주세요" 를 안내한다. 교체·삭제 시 이전 저장소 파일을 지운다. |
| FR-415 | **카테고리**(선택): 선생님 카테고리 중 하나를 고르는 Select. 맨 위 "선택 안 함". 옆에 [카테고리 관리] 링크(설정 탭으로). |
| FR-416 | **가격**(선택): 숫자만 입력, 입력 중 천 단위 콤마 표시, 단위 "원". 0 ~ 100,000,000 정수. 비우면 가격 없음(카드에 표시하지 않음), `0` 은 "0원" 으로 그대로 표시한다. |
| FR-417 | 수정은 같은 모달. 삭제는 확인 대화상자: "상품과 이 상품의 클릭 기록이 함께 지워져요. 기록을 남기려면 **숨기기**를 쓰세요." |
| FR-418 | 선생님당 상품 최대 **200개**(초과 시 400 "상품은 200개까지 등록할 수 있어요"). |

### 5.3 카테고리

| ID | 요구사항 |
|---|---|
| FR-420 | 상점 생성 시 기본 카테고리 **발레복 · 레오타드 · 기구 · 슈즈 · 용품** 을 이 순서로 만든다. |
| FR-421 | 설정 탭에서 추가·이름 변경·삭제·순서 변경(▲▼). 이름 1~20자, 선생님 안에서 중복 불가(대소문자·앞뒤 공백 무시), 최대 20개. |
| FR-422 | 카테고리를 지우면 그 카테고리의 상품은 **"카테고리 없음"** 이 된다(상품은 지우지 않는다, `ON DELETE SET NULL`). 확인 문구에 영향받는 상품 수를 보여 준다. |

### 5.4 목록 · 노출 관리 (선생님)

| ID | 요구사항 |
|---|---|
| FR-425 | 상품 탭 목록 열: 순서(▲▼) · 이미지 썸네일 · 타이틀(+ 링크 도메인) · 카테고리 · 가격 · **공개 스위치** · 누적 클릭 · [수정][삭제]. 데스크톱 표 / 모바일 카드는 `DataTable` 한 정의로(디자인 시스템 규칙). |
| FR-426 | **공개 스위치**를 끄면 공개 상점에서 즉시 사라진다. 클릭 기록은 유지되고 통계에도 "숨김" 표시와 함께 남는다. |
| FR-427 | **표시 순서**는 선생님이 정한 순서(`sortOrder`)이고 공개 상점도 같은 순서다. 새 상품은 맨 위. ▲▼ 로 한 칸씩 옮기면 전체 순서를 한 번에 저장한다(`utils/reorder.js:moveItem`). |
| FR-428 | 카테고리 필터 칩(전체 + 카테고리)과 타이틀 검색(`koreanSearch` 초성 검색 재사용). |

### 5.5 공개 상점 화면 (학부모, 비로그인)

| ID | 요구사항 |
|---|---|
| FR-430 | 상단: 상점 이름(페이지 `<title>` 도 같음), 소개(줄바꿈 유지). 하단: 하단 안내문(있을 때만). |
| FR-431 | **카테고리 칩**: [전체] + 공개 상품이 1개 이상 있는 카테고리만, 선생님이 정한 순서. 카테고리 없는 상품은 [전체] 에만 나온다. 칩 선택은 주소의 `?c=<categoryId>` 에 남겨 새로고침·공유해도 유지된다. |
| FR-432 | **상품 카드 그리드**: 모바일 2열 · 태블릿 3열 · 데스크톱 4열. 카드 = 정사각 이미지(없으면 회색 바탕 + 아이콘) · 카테고리 라벨 · 타이틀(2줄 말줄임) · 가격(`32,000원`, 있을 때만) · 링크 도메인(`coupang.com ↗`, 링크 있을 때만). |
| FR-433 | 링크가 있는 카드는 **카드 전체가 `<a href="상품주소" target="_blank" rel="noopener noreferrer">`** 다. 링크가 없는 카드는 누를 수 없고(커서·호버 없음) 클릭도 기록하지 않는다. |
| FR-434 | 공개 상품이 없으면 "아직 등록된 상품이 없어요". 로딩 중에는 카드 스켈레톤. 네트워크 오류는 [다시 시도]. |
| FR-435 | 응답에는 공개 상품의 **화면에 필요한 필드만** 담는다(02 §4 화이트리스트). 선생님 id·저장소 경로·숨김 상품·클릭 수는 내려가지 않는다. |
| FR-436 | 이미지는 `loading="lazy"`, 고정 비율 상자로 레이아웃 흔들림이 없게 한다. |

### 5.6 클릭 · 방문 기록

| ID | 요구사항 |
|---|---|
| FR-440 | 카드를 누르는 순간(기본 이동은 막지 않는다) `navigator.sendBeacon('POST /api/shop/public/:publicId/products/:productId/click?visitorKey=…')` 를 보낸다. `sendBeacon` 이 없거나 `false` 를 돌려주면 `fetch(…, {method:'POST', keepalive:true})` 로 한 번 더 시도한다. 기록 실패가 이동을 절대 막지 않는다. |
| FR-441 | 서버는 상품이 **그 상점의 공개 상품이고 링크가 있을 때만** 기록한다. 아니면 404(기록 없음). |
| FR-442 | **중복 방지**: 같은 `visitorKey` 가 같은 상품을 **10초 안에** 다시 누르면 기록하지 않는다(두 번 탭·뒤로 왔다 다시 누름). 그 이상은 별도 클릭으로 센다. |
| FR-443 | **방문**: 공개 상점을 연 브라우저 세션에서 1회 `POST …/view?visitorKey=…`(sessionStorage 플래그). 새로고침·칩 이동은 다시 세지 않는다. 서버도 같은 `visitorKey` 의 방문을 **30분 안에 한 번만** 기록한다(sessionStorage 가 막힌 인앱 브라우저 대비). |
| FR-444 | 기록에는 **상점 주인(선생님 id), 상품 id, 종류(view/click), visitorKey, 시각**만 저장한다. IP·User-Agent·리퍼러는 저장하지 않는다. |
| FR-445 | 선생님이 자기 상점의 [미리 보기]로 들어가 누른 것도 기록된다(로그인 여부를 보지 않는 공개 경로이므로). 통계 화면에 이 점을 한 줄로 안내한다(Q-6). |

### 5.7 통계 (선생님)

| ID | 요구사항 |
|---|---|
| FR-450 | 통계 탭 상단 기간 선택: **최근 7일 · 30일(기본) · 90일 · 전체**. 기간은 "지금부터 N×24시간 전" 기준. |

| FR-453 | **카테고리별 클릭** 합계(막대). 카테고리 없음은 "카테고리 없음". |
| FR-454 | 기록이 하나도 없으면 "아직 기록이 없어요. 상점 링크를 학부모에게 보내 보세요 [링크 복사]". |
| FR-455 | 삭제된 상품의 클릭은 통계에서 사라진다(CASCADE, FR-417). 숨김 상품은 남는다. |

### 5.8 권한 · 보안

| ID | 요구사항 |
|---|---|
| FR-460 | 선생님 API(`/api/shop/*`, `/public` 제외)는 `verifyToken` + `rejectParents`. 모든 조회·수정은 **토큰의 사용자 id 로 범위를 제한**한다. 다른 선생님의 상품·카테고리 id 는 404(존재 여부 비공개). |
| FR-461 | 공개 API(`/api/shop/public/*`)는 인증 없음. 응답은 화이트리스트 직렬화(02 §4)만 쓴다 — 새 컬럼이 생겨도 실수로 새지 않도록 테스트가 필드 목록을 고정한다. |
| FR-462 | 상품 주소는 저장 시(서버)와 렌더 시(클라이언트) **두 번** `http/https` 를 확인한다. 렌더 시 통과하지 못하면 링크 없는 카드로 그린다. |
| FR-463 | 이미지 형식은 **확장자로** 판단한다(브라우저 `Content-Type` 은 믿지 않는다). 저장소 경로 `shop/{userId}/{uuid}/{ascii이름}` — 추측 불가, 덮어쓰기 없음, 한글 키 금지(Supabase 제약). |
| FR-464 | 공개 경로 레이트 리밋: 읽기 visitor당 15분 300회, 기록(view/click) visitor당 15분 120회. 일반 `apiLimiter`(IP당 200)에서는 공개 상점 경로를 뺀다 — 같은 와이파이의 학부모들이 한 칸을 나눠 쓰지 않도록(공개 채팅과 같은 이유). |
| FR-465 | 소개·안내문·타이틀은 **텍스트로만** 렌더한다(HTML 해석 없음, React 기본 이스케이프). |
| FR-466 | 선생님 행이 삭제되면 상점·카테고리·상품·기록이 CASCADE 로 지워진다. 저장소의 이미지 파일은 남는다 — FAQ 파일과 같은 기존 한계이며, 경로가 난수라 외부에서 찾을 수 없다(03 §6). |

## 7. 화면 목록

| 화면 | 경로 | 비고 |
|---|---|---|
| 공개 상점 | `/shop/:publicId` | 비로그인, 앱 헤더 없음 |
| 추천 상품 › 상품 | `/products` | 선생님 메뉴 "추천 상품" 신설, 상단에 공개 링크 카드 |
| 추천 상품 › 통계 | `/products/stats` | 같은 페이지의 탭 |
| 추천 상품 › 설정 | `/products/settings` | 상점 이름·소개·안내문·공개, 카테고리 관리 |
| 상품 등록/수정 | (모달) | 데스크톱 가운데 모달 / 모바일 바텀시트 |

> 선생님 경로는 `/products`, 공개 경로는 `/shop/` 로 **접두어를 분리**한다. 같은 `/shop` 아래에 두면 공개 페이지 판별(`pathname.startsWith('/shop/')`)이 선생님 하위 경로까지 잡아 버린다.

## 8. 수용 기준

- AC-1 타이틀만 입력하고 저장하면 상품이 생기고, 공개 상점에 이미지 자리 회색·가격 없음·누를 수 없는 카드로 보인다.
- AC-2 타이틀을 비우고 저장하면 저장되지 않고 필드 아래에 안내가 뜬다. API 로 직접 보내도 400.
- AC-3 주소 `javascript:alert(1)` 은 저장되지 않는다. `coupang.com/vp/products/1` 은 `https://coupang.com/vp/products/1` 로 저장된다.
- AC-4 로그아웃 상태의 새 브라우저(시크릿 창)에서 공개 링크를 열면 상점이 보인다. 로그인한 학부모·선생님이 열어도 같은 화면이다.
- AC-5 공개 OFF 로 바꾸면 공개 링크는 "지금은 볼 수 없는 페이지예요". 다시 켜면 그대로 돌아온다.
- AC-6 "기구" 칩을 누르면 기구 상품만 보이고, 주소에 `?c=` 가 붙어 새로고침해도 유지된다.
- AC-7 링크 있는 카드를 누르면 상품 주소가 새 창으로 열리고, 통계 탭의 해당 상품 클릭이 1 늘어난다. 10초 안에 다시 누르면 늘지 않는다.
- AC-8 숨긴 상품은 공개 상점에서 사라지지만 통계 표에는 "숨김" 으로 남는다. 삭제하면 통계에서도 사라진다.
- AC-9 다른 선생님 계정으로 내 상품 id 를 수정·삭제·이미지 업로드하면 404.
- AC-10 학부모 토큰으로 `/api/shop`(공개 경로 외)을 부르면 403.
- AC-11 공개 API 응답에 `userId`, `imagePath`, `isVisible=false` 상품, 클릭 수가 없다.
- AC-12 카테고리를 지우면 그 상품들은 "카테고리 없음" 이 되고 상품은 남는다.

## 9. 열린 질문

구현은 **기본 가정**으로 진행하고, 답이 다르면 해당 부분만 바꾼다.

| # | 질문 | 기본 가정 |
|---|---|---|
| Q-1 | 카테고리는 선생님이 직접 추가·수정할 수 있어야 하나요, 고정 목록이면 되나요? | **선생님이 관리** + 기본값 5개(발레복·레오타드·기구·슈즈·용품) |
| Q-2 | 로그인한 학부모 포털(일정·사진 탭)에도 "추천 상품" 탭을 둘까요? | 이번엔 **공개 링크만**. 포털 탭은 2차(학부모가 여러 선생님에 연결될 수 있어 탭 안에서 선생님을 고르는 화면이 필요) |
| Q-3 | 이미지는 파일 업로드만 되면 되나요, 쇼핑몰 이미지 주소 붙여넣기도 필요한가요? | **업로드만**. 외부 이미지 주소는 핫링크 차단으로 자주 깨진다 |
| Q-4 | 쿠팡 파트너스 같은 **제휴 링크**를 쓰시나요? (공정위 추천·보증 지침상 "수수료를 받을 수 있음" 고지가 필요) | 상점 **하단 안내문** 입력란을 두고, 쓸지는 선생님이 정한다 |
| Q-5 | 카카오톡에 링크를 보낼 때 상점 이름·대표 이미지가 미리보기로 뜨면 좋을까요? | 2차. SPA 라 서버에서 메타 태그를 끼워 넣는 작업이 따로 필요하다 |
| Q-6 | 선생님 본인의 미리 보기 클릭도 통계에서 빼야 하나요? | 이번엔 **세지만 안내**. 빼려면 미리 보기 링크에 표시를 달아 기록을 건너뛰게 할 수 있다(작은 작업) |
| Q-7 | 상품에 짧은 추천 문구(예: "초등 저학년 추천")가 필요하신가요? | 이번엔 없음. 필요하면 `description` 컬럼 하나로 추가 |
