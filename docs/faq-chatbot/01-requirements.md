# 01. 요구사항 정의서 — FAQ 챗봇

- 문서 버전: 1.0
- 작성일: 2026-08-22
- 대상 시스템: 리듬체조 출석 관리 시스템 (React 18 + Vite / Node.js Express / PostgreSQL)

---

## 1. 배경 및 목적

학원 운영자는 학부모로부터 수업 시간, 준비물, 대회 일정, 결제 등 **반복되는 질문**을 개별적으로 받고 있다.
반복 문의를 줄이기 위해, 운영자가 등록한 FAQ를 근거로 **AI가 자동 응답하는 학부모 전용 채팅 페이지**를 제공한다.

목적:

1. 반복 문의 응대 시간 절감
2. 학부모가 로그인·앱 설치 없이 링크 하나로 질문 가능
3. 등록되지 않은 내용은 **답변하지 않음**을 보장하여 잘못된 안내 방지
4. 실제 질문 로그를 확보해 FAQ를 지속 보강

---

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 관리자 | 본 시스템에 로그인하는 계정 사용자(학원 원장/강사). 기존 `users` 테이블의 사용자. |
| 시스템 관리자 | `role = 'admin'` 사용자. `/admin` 영역에서 전체 사용자 데이터 조회 가능. |
| 학부모 | 로그인하지 않고 공개 채팅 링크로 접속하는 방문자. |
| FAQ | 관리자가 등록한 (질문, 답변) 쌍. 별도 분류(카테고리)는 두지 않는다. |
| 채팅 채널(channel) | 관리자 1명에게 발급되는 공개 채팅창. 고유 `publicId`(랜덤 토큰)를 가진다. |
| 채팅 세션(session) | 한 학부모(브라우저)가 채널에서 이어가는 하나의 대화. |
| 미답변 질문 | AI가 관련 FAQ를 찾지 못해 안내 문구로 응답한 질문. |

---

## 3. 범위

### 3.1 포함 (MVP)

- 메인 메뉴에 `FAQ` 추가
- FAQ 목록/등록/수정/삭제 (관리자 본인 데이터)
- 채팅 링크 확인 및 복사
- 공개 채팅 페이지(로그인 불필요) 및 질문 입력
- FAQ 기반 AI 답변 + 근거 없을 때 안내 문구
- 관리자 화면에서 대화 내역(질문/답변) 조회
- 시스템 관리자(`/admin/faq`)에서 전체 사용자 FAQ·대화 조회

### 3.2 제외 (2차 이후 검토)

- 관리자가 채팅창에서 학부모에게 **직접 답장**하는 실시간 상담 기능
- 미답변 질문을 클릭 한 번으로 FAQ로 전환하는 기능
- 카카오 알림톡 연동, 이메일 알림
- 파일/이미지 업로드, 음성 입력
- FAQ 벡터 임베딩 검색(FAQ 수가 수백 건을 넘어설 때 재검토)
- 다국어 지원 (한국어만 제공)

|---|---|---|

| US-09 | 시스템 관리자 | 전체 사용자의 FAQ 운영 현황을 한 화면에서 점검하고 싶다. |

## 5. 기능 요구사항

표기: **[필수]** = MVP 범위, **[선택]** = 2차

### 5.1 메뉴 / 진입점

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 메인 헤더 네비게이션(`client/src/App.jsx`의 `navLinks`)에 `FAQ`(아이콘 💬) 항목을 추가한다. 데스크톱 메뉴와 모바일 전체화면 메뉴 모두에 노출된다. | 필수 |
| FR-02 | `/faq` 경로는 `ProtectedRoute`로 보호한다. 비로그인 사용자는 `/login`으로 이동한다. | 필수 |
| FR-03 | 관리자 사이드바(`client/src/components/admin/AdminLayout.jsx`의 `adminMenuItems`)에 `FAQ` 항목을 추가하고 `/admin/faq` 라우트를 제공한다. `AdminRoute`로 `role === 'admin'`만 접근 가능하다. | 필수 |
| FR-04 | `/chat/:publicId` 경로는 **인증 없이** 접근 가능해야 한다. 로그인 여부와 무관하게 동일 화면을 보여준다. | 필수 |

### 5.2 FAQ 관리 (요구사항 1, 2)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | FAQ 목록 화면은 로그인한 사용자 **본인이 등록한 FAQ만** 표시한다. (시스템 관리자는 `/admin/faq`에서 사용자 필터로 전체 조회) | 필수 |
| FR-11 | FAQ 등록 시 입력 항목: **질문(필수, 200자 이내)**, **답변(필수, 2000자 이내)**, 공개 여부(기본 공개). **카테고리는 두지 않는다.** | 필수 |
| FR-12 | FAQ 수정: 위 모든 항목을 수정할 수 있다. 수정 시 `updatedAt`이 갱신된다. | 필수 |
| FR-13 | FAQ 삭제: 확인 절차(확인 모달 또는 `window.confirm`) 후 삭제한다. 삭제된 FAQ는 이후 AI 답변 근거에서 제외된다. 이미 전송된 대화 기록은 유지된다. | 필수 |
| FR-14 | FAQ 목록은 질문·답변 텍스트 검색을 제공한다. 검색은 기존 `client/src/utils/koreanSearch.js`의 초성/부분 검색 유틸을 재사용한다. 카테고리 필터는 제공하지 않는다. | 필수 |
| FR-15 | FAQ 목록은 `displayOrder` 기준 정렬을 지원하며, 기존 수업 목록의 순서 변경 유틸(`client/src/utils/reorder.js`)과 동일한 방식으로 순서를 바꿀 수 있다. | 선택 |
| FR-15a | **모바일에서는 카드를 왼쪽으로 스와이프하면 [수정]·[삭제] 버튼이 나타난다.** 버튼을 상시 노출하지 않는다. 스와이프 거리 50px 이상에서 열리고, 반대로 밀거나 카드를 탭하거나 다른 카드를 열면 닫힌다. Pointer Events로 구현해 터치와 마우스 드래그를 모두 지원한다. 목록 상단에 "← 카드를 왼쪽으로 밀면 수정·삭제가 나옵니다" 안내를 1회 표시한다. | 필수 |
| FR-15b | 데스크톱(표 레이아웃)에서는 기존대로 행 우측에 [수정]·[삭제] 버튼을 노출한다. | 필수 |
| FR-16 | 비공개(`isPublished = false`) FAQ는 AI 답변 근거에서 제외된다. | 필수 |
| FR-17 | FAQ 생성/수정/삭제는 기존 `logAction` 미들웨어로 감사 로그(`logs` 테이블)에 기록한다. 액션명: `CREATE_FAQ`, `UPDATE_FAQ`, `DELETE_FAQ`. | 필수 |

### 5.3 채팅 링크 (요구사항 3)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 사용자가 처음 `/faq` 화면에 진입하면 해당 사용자의 채팅 채널이 없을 경우 **자동으로 1개 생성**한다. | 필수 |
| FR-21 | 채널은 추측 불가능한 `publicId`(최소 22자 이상의 URL-safe 랜덤 문자열, `crypto.randomUUID()` 또는 `crypto.randomBytes(16).toString('base64url')`)를 가진다. | 필수 |
| FR-22 | FAQ 화면 **상단 우측의 공유 아이콘 버튼** 하나로 링크 복사를 제공한다. 누르면 `https://<도메인>/chat/<publicId>` 전체 링크가 클립보드에 복사되고 토스트로 피드백한다. 텍스트 라벨 없이 아이콘만 노출하며 `title`/`aria-label`에 "학부모 질문 링크 복사"를 지정한다. 터치 영역은 최소 44×44px. | 필수 |
| FR-22a | 링크 전문을 보여주는 별도 배너/섹션은 **두지 않는다**. 화면에는 FAQ 목록과 상단 아이콘만 남긴다. | 필수 |
| FR-23 | 복사는 `navigator.clipboard.writeText`를 사용하되, 미지원·비HTTPS 환경을 위해 `textarea` + `document.execCommand('copy')` 폴백을 둔다. (모바일 사파리 대응) | 필수 |
| FR-24 | 관리자는 채널의 **인사말(greeting)**, **채널 이름**(예: "○○리듬체조 문의"), **답변 불가 안내 문구**를 수정할 수 있다. 진입점은 FAQ 화면 상단 우측의 설정(톱니) 아이콘이며, 모달로 연다. | 필수 |
| FR-25 | 관리자는 채널을 **비활성화**할 수 있다. 비활성 채널 링크로 접속하면 "현재 문의를 받고 있지 않습니다" 안내만 보인다. | 필수 |
| FR-26 | 링크 재발급(`publicId` 재생성) 기능을 제공한다. 재발급 시 기존 링크는 즉시 무효화되며, 확인 절차를 거친다. | 선택 |

### 5.4 학부모 공개 채팅 (요구사항 4)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | `/chat/:publicId` 접속 시 채널 이름과 인사말을 보여주고 메시지 입력창을 제공한다. 로그인 요구 없음. | 필수 |
| FR-31 | 존재하지 않거나 비활성 `publicId`인 경우 404 안내 화면을 표시한다. 다른 채널 정보나 사용자 정보를 노출하지 않는다. | 필수 |
| FR-32 | 학부모 식별자(`visitorKey`)는 브라우저 `localStorage`에 UUID로 저장한다. 같은 브라우저로 재접속하면 이전 대화가 이어진다. | 필수 |
| FR-33 | 채팅 진입 시 **대화명 입력 화면을 먼저 표시한다.** 대화명을 입력해야 질문을 시작할 수 있다(1~20자, 공백만 입력 불가). 입력한 대화명은 `localStorage`에 저장해 재접속 시 입력 단계를 건너뛴다. | 필수 |
| FR-33a | 대화명 입력 화면에는 실명 대신 "○○ 어머님" 같은 표시명을 권장한다는 안내와, 입력 내용이 관리자에게 저장·전달된다는 고지를 함께 노출한다. 전화번호·주소 등 그 밖의 개인정보는 수집하지 않는다. | 필수 |
| FR-33b | 대화 시작 후 채팅 헤더에 "○○님으로 대화 중"을 표시하고, 학부모 말풍선에 대화명을 라벨로 표시한다. | 필수 |
| FR-34 | 메시지 1건은 500자를 초과할 수 없다. 초과 시 전송 버튼이 비활성화되고 잔여 글자 수를 표시한다. | 필수 |
| FR-35 | 전송 후 답변 생성 중에는 로딩 표시("답변을 작성하고 있어요...")를 노출하고 중복 전송을 막는다. | 필수 |
| FR-36 | 자주 묻는 질문 상위 N개(기본 5개)를 **추천 질문 버튼**으로 노출해 클릭만으로 질문할 수 있게 한다. | 선택 |
| FR-37 | 화면은 모바일 우선으로 구성한다. 기존 `useIsMobile` 훅과 CSS 변수를 사용하고, 입력창은 하단 고정, 메시지 영역은 스크롤된다. | 필수 |
| FR-37a | **모바일에서 입력창에 포커스해 키보드가 올라와도 채팅 화면은 전체 화면을 유지한다.** `visualViewport`의 height/offsetTop에 맞춰 컨테이너를 고정하고(`position: fixed`), 페이지 자체는 스크롤되지 않게 한다. 입력창은 항상 키보드 위에 보이고, 포커스 시 마지막 메시지로 스크롤한다. | 필수 |
| FR-37b | iOS Safari가 포커스 시 화면을 확대하지 않도록 입력 요소의 글자 크기는 **16px 이상**으로 한다. | 필수 |
| FR-39 | 학부모 화면은 8초 주기로 새 메시지를 조회해 **관리자 답변을 자동으로 표시**한다. 탭이 비활성이거나 전송 중일 때는 조회하지 않는다. | 필수 |
| FR-38 | 메시지는 항상 **텍스트로만 렌더링**한다. HTML/마크다운을 그대로 삽입하지 않는다(XSS 방지). 줄바꿈만 유지한다. | 필수 |

### 5.5 AI 답변 (요구사항 5)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 학부모 질문이 들어오면 서버는 해당 채널 소유자의 **공개 FAQ 전체**를 근거로 **Google Gemini API**를 호출해 답변을 생성한다. 상세 설계는 [03-ai-answer-design.md](./03-ai-answer-design.md) 참조. | 필수 |
| FR-41 | AI는 FAQ에 없는 내용을 추측해 답하지 않는다. 근거가 없으면 `answered = false`를 반환하고, 서버는 고정 안내 문구로 응답을 대체한다. | 필수 |
| FR-42 | 기본 안내 문구: **"죄송합니다. 등록된 FAQ에서 관련 내용을 찾지 못했습니다. 자세한 내용은 담당 선생님께 문의해 주세요."** 채널별로 수정 가능해야 한다. | 필수 |
| FR-43 | 답변에 사용된 FAQ id 목록을 저장해 관리자 화면에서 "근거 FAQ"로 확인할 수 있다. | 필수 |
| FR-44 | 직전 대화 맥락(최근 6턴)을 함께 전달해 "그럼 그건요?" 같은 이어지는 질문을 처리한다. | 필수 |
| FR-45 | AI 호출 실패(타임아웃, API 오류)나 API 키 미설정 시에도 사용자에게는 안내 문구로 정상 응답하고, 서버 로그와 `chat_messages.status`에 실패를 기록한다. | 필수 |
| FR-46 | 등록된 공개 FAQ가 0건이면 AI를 호출하지 않고 즉시 안내 문구를 반환한다(불필요한 비용 방지). | 필수 |
| FR-47 | 답변 응답 시간은 정상 조건에서 10초 이내를 목표로 한다. 초과 시 타임아웃 처리 후 안내 문구로 대체한다. | 필수 |

### 5.6 관리자 대화 확인 (요구사항 6)

| ID | 요구사항 | 우선순위 |
|---|---|---|

| FR-54 | 대화 목록은 페이지네이션(기본 20건) 또는 더보기 방식으로 조회한다. | 필수 |
| FR-55 | 관리자는 대화 세션을 삭제할 수 있다. 삭제 시 해당 세션의 메시지도 함께 삭제된다(`ON DELETE CASCADE`). | 필수 |
| FR-56 | 시스템 관리자는 `/admin/faq`에서 사용자별 필터(`filterUserId`)로 전체 사용자의 FAQ와 대화를 조회할 수 있다. 기존 컨트롤러의 `filterUserId` 패턴을 따른다. | 필수 |
| FR-57 | 관리자는 대화 상세에서 **학부모에게 직접 답변**을 보낼 수 있다. 답변은 `role='admin'` 메시지로 저장되고, 학부모 화면에 "선생님" 말풍선으로 표시된다. 500자 이내. | 필수 |
| FR-57a | 관리자가 답변하면 해당 대화의 미답변 수는 0으로 초기화되고 `lastAdminReplyAt`이 기록된다. | 필수 |
| FR-58 | 관리자는 채널 설정에서 **AI 자동 답변을 끌 수 있다**(`aiEnabled`). 끄면 학부모 질문에 AI를 호출하지 않고 접수 안내 문구만 남기며, 해당 대화는 미답변으로 집계되어 관리자가 직접 답변한다. | 필수 |
| FR-58a | AI를 끈 상태의 접수 안내 문구(`pendingMessage`)는 관리자가 수정할 수 있다. 기본값: "문의가 접수되었습니다. 선생님이 확인 후 답변드릴게요." | 필수 |
| FR-58b | AI가 꺼져 있으면 학부모 화면 헤더에 "선생님 직접 답변" 배지를 노출하고, FAQ 미등록 안내는 표시하지 않는다. 관리자 FAQ 화면 상단에도 안내를 표시한다. | 필수 |

## 9. 가정 및 결정 필요 사항

### 9.1 가정

- 학원 1곳당 FAQ 수는 100건 이하이며, 전체 FAQ를 프롬프트에 넣어도 컨텍스트 한도에 여유가 있다.
- 동시 접속 학부모 수는 수십 명 수준으로, 스트리밍 응답 없이 단일 요청/응답으로 충분하다.
- 학부모는 대부분 모바일에서 접속한다.
- 대화 데이터 보관 기간에 대한 별도 규정은 없다(기본 무기한 보관, 관리자가 삭제 가능).

### 9.2 결정 필요

| # | 항목 | 권장안 |
