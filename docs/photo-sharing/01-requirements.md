# 대회 사진 · 영상 공유 — 요구사항

> 상태: **1차 초안 — 2026-08-23** · 관련: [README](./README.md), [02-data-model-api.md](./02-data-model-api.md) ·
> 이전 분석 [parent-portal §10.3](../parent-portal/01-requirements.md#103-사진-공유--google-drive-앨범--자녀-얼굴-인식-필터) 을 대체한다(달라진 점은 §9).

## 1. 배경 및 목적

대회가 끝나면 선생님과 학부모들이 찍은 사진·영상이 카톡방에 흩어져 올라오고, 화질이 깎이고, 나중에 "우리 아이 사진"만 찾기 어렵다.
학부모 포털(일정·신청·확정)이 생기면서 **"이 대회에 누가 참가했는지"** 를 앱이 알게 되었으므로,
그 참가자(확정된 자녀)의 학부모끼리 **원본 화질 그대로 한 곳(Google Drive)** 에 모으고, **자기 아이 사진만** 걸러 볼 수 있게 한다.

이 기능의 목적:

1. 선생님이 이벤트 상세에서 **폴더 이름만 넣으면** Google Drive 에 앨범 폴더가 생긴다. Drive 를 따로 열어 만들고 링크를 복사해 오지 않는다.
2. **확정된 학부모**는 앱에서 **사진·영상을 그 폴더로 올리고**, 다른 학부모·선생님이 올린 사진도 본다.
3. 사진이 올라오면 **얼굴 인덱스(벡터)를 Supabase 에 저장**해 두었다가, 학부모가 자녀 얼굴을 등록하면 **자기 아이 사진만** 모아 볼 수 있다.
4. 사진 바이트는 선생님 Drive 에만 있고, 앱은 **파일 id·메타·벡터**만 가진다(저장 비용 0, 선생님이 언제든 Drive 에서 통째로 가져갈 수 있다).

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 선생님 | `users.role='user'`. 이벤트·학생·앨범의 소유자. 메모의 "관리자" |
| 학부모 | `users.role='parent'`. 카카오로 로그인, 선생님 1명에게 속함 |
| 자녀 | `parent_children.status='linked'` 로 학생(`students`)에 연결된 행 |
| 이벤트 | `events` 행. 앨범은 **대회(`competition`) · 스페셜(`special`)** 에만 붙는다. 휴관일에는 없다 |
| 이벤트 상세 | 선생님 쪽 이벤트 수정/신청 현황 화면. 메모의 **"프로젝트 상세"** 를 이렇게 해석한다(Q-9) |
| 확정 학부모 | 해당 이벤트에 **자녀가 확정된** 학부모. 정확한 정의는 FR-200 |
| Drive 연결 | 선생님이 설정에서 Google 계정을 OAuth 로 연결한 상태(`google_drive_accounts`) |
| 루트 폴더 | Drive 연결 시 선생님 My Drive 에 한 번 만드는 상위 폴더(기본 이름 `RG Manager`). 앨범 폴더는 모두 이 아래에 생긴다 |
| 앨범 폴더 | 선생님이 이벤트 상세에서 이름을 넣어 만든 Drive 폴더. **이벤트당 1개** (`events.driveFolderId`) |
| 앨범 | 앨범 폴더 + 앱이 아는 미디어 목록·태그. 학부모가 보는 화면 단위 |
| 미디어 | 앨범에 올라간 **사진 또는 영상** 1개 (`event_media`). `kind = 'image' \| 'video'` |
| 업로더 | 미디어를 올린 사람. 선생님 또는 확정 학부모 |
| 얼굴 인덱스 | 사진 속 얼굴 1개의 **128차원 벡터 + 위치(상대 좌표)**. `media_faces`, Supabase Postgres(pgvector) |
| 기준 얼굴 | 학부모가 자녀별로 등록한 얼굴 사진(1~3장)에서 뽑은 벡터. `child_face_profiles` |
| 태그 | 미디어 ↔ 학생 연결(`media_tags`). 출처: 자동(`face`) / 후보(`candidate`) / 수동(`manual`, 선생님) / 학부모 확인(`parent_confirmed`) / 제외(`excluded`) |
| 축소본 | 업로드 직후 **브라우저가 만든** 긴 변 1,600px JPEG(≤1MB). 얼굴 인덱싱 입력으로만 쓰고 저장하지 않는다 |

## 3. 범위

### 3.1 포함

- 선생님 **Google Drive 연결**(OAuth, `drive.file`) · 루트 폴더 생성 · 연결 해제
- 이벤트 상세에서 **앨범 폴더 생성**(이름 입력 → Drive 폴더 생성 → 링크 공유 설정) · 이름 변경 · 업로드 받기 토글
- **업로드**: 선생님 + 확정 학부모, 사진·영상, 다중 선택, 브라우저 → Drive 직접 전송(재개 가능, 진행률)
- **앨범 조회**: 확정 학부모·선생님, 썸네일 그리드 · 확대 뷰어 · 영상 재생 · 원본 보기(Drive)
- **얼굴 인덱싱**: 사진 업로드 완료 시 자동(서버, face-api.js) → Supabase pgvector 저장. 실패분 재분석 배치
- **자녀 기준 얼굴 등록**(학부모, 1~3장, 동의) → 즉시 매칭
- **"우리 아이만" 필터** + "혹시 우리 아이?" 확인(맞아요/아니에요)
- 선생님 **앨범 관리**: 숨김/삭제/수동 태그/재분석/재매칭, 업로드 활동 로그
- 삭제·정합성(Drive 에서 사라진 파일, 이벤트 삭제, 계정 삭제, 연결 해제)

### 3.2 제외 (이번 범위 밖)

- 앱 **밖에서** Drive 폴더에 직접 넣은 파일의 자동 동기화 — `drive.file` 범위는 앱이 만든 파일만 본다(§02 리스크 R-1). 필요해지면 `drive.readonly`(Google 검수 필요) 추가
- **영상 얼굴 인식**(프레임 추출). 영상은 수동 태그만
- 학부모가 다른 사람이 올린 미디어 삭제·숨김, 댓글·좋아요·다운로드 묶음(zip)
- 원본 다운로드 차단(Drive 링크를 보여주는 이상 불가능) · 워터마크
- 생체정보(얼굴 벡터) 관련 **법적 검토** — 실서비스 전 항목(FR-12b 승계, NFR-5)
- 선생님 대표 얼굴 등록(FR-265 선택) · 학부모 앱 내 알림(§10.7 인프라 이후)

### 3.3 전제

[학부모 포털 MVP](../parent-portal/01-requirements.md) §5 가 구현되어 있어야 한다 — 학부모 계정, 자녀 연결, 이벤트, 신청 → 확정.
**확정** 이 앨범 접근의 열쇠이므로 FR-72(대회 확정)·`competition_students` 가 먼저 있어야 한다.

## 4. 사용자 스토리

**선생님**

- T-1 대회 이벤트를 만든 뒤 상세에서 "2026 전국 꿈나무 대회" 라고 폴더 이름을 넣으면 내 Google Drive 에 폴더가 생기고, 더 할 일이 없다.
- T-2 대회 당일 내가 찍은 사진 수십 장과 영상 몇 개를 앱에서 그 폴더로 한 번에 올린다.
- T-3 학부모들이 올린 사진도 앨범 한 곳에서 보고, 잘못 올라온 사진은 숨기거나 지운다.
- T-4 얼굴이 작게 나와 자동으로 못 찾은 사진은 내가 아이 이름을 직접 붙여 준다.
- T-5 학부모가 처음에 Drive 연결을 안 한 채 폴더를 만들려 하면, 설정으로 안내받는다.

**학부모**

- P-1 우리 아이가 확정된 대회 앨범에 내 휴대폰 사진·영상을 올린다. Google 계정은 필요 없다.
- P-2 앨범에서 선생님·다른 학부모가 올린 사진도 모두 본다. 원본은 Drive 링크로 연다.
- P-3 내 정보에서 아이 얼굴 사진을 2장 등록했더니, 지난 대회 앨범에서도 우리 아이 사진이 바로 모인다.
- P-4 "혹시 우리 아이?" 로 묶인 사진에서 [맞아요]/[아니에요] 를 눌러 정리한다.
- P-5 확정되지 않은 이벤트의 앨범은 보이지 않고, 이유를 안내받는다.

### 5.2 선생님 Google Drive 연결

| ID | 요구사항 |
|---|---|
| FR-210 | 선생님 **설정 > Google Drive** 카드: [연결하기] → Google OAuth 동의(범위 `https://www.googleapis.com/auth/drive.file`, `access_type=offline`, `prompt=consent`) → 콜백에서 토큰을 `google_drive_accounts` 에 저장(카카오 토큰 저장 패턴과 동일, 서버에만 둔다) → 설정으로 돌아와 **연결된 Google 이메일**과 Drive **남은 용량**을 보여 준다. |
| FR-211 | 연결 직후 선생님 My Drive 에 **루트 폴더**(기본 이름 `RG Manager`)를 만들고 id 를 저장한다. 이미 저장된 id 가 살아 있으면(files.get 200) 재사용한다. 설정에서 루트 폴더 이름을 바꿀 수 있다(Drive 이름도 함께 변경). |
| FR-212 | access token 만료(1시간)는 refresh token 으로 **자동 갱신**한다. 갱신 실패(`invalid_grant` — 선생님이 Google 에서 권한을 철회)하면 `status='error'` 로 바꾸고, 선생님 화면 상단에 "Google Drive 연결이 끊어졌어요 [다시 연결]" 배너, 학부모 업로드 버튼은 "지금은 업로드할 수 없어요(선생님 확인 중)" 로 비활성. 조회는 계속된다(FR-294). |
| FR-213 | Drive 연결 전에 [앨범 폴더 만들기] 를 누르면 "먼저 설정에서 Google Drive 를 연결해 주세요" + 설정 링크. |
| FR-214 | 선생님 계정당 Google 계정 **1개**. [연결 해제] 는 토큰 revoke + 행 삭제. 이전 계정으로 만든 앨범 폴더는 그 계정 Drive 에 남으므로, 앨범은 `events.driveAccountId` 로 어느 연결로 만들었는지 기억한다. 다른 계정으로 재연결하면 이전 앨범은 "이전 Google 계정의 앨범 — 조회만 가능" 으로 표시하고 업로드·삭제·재분석을 막는다. |
| FR-215 | OAuth `state` 는 선생님 JWT 에 묶인 1회용 난수(10분). 콜백은 `state` 가 맞을 때만 토큰을 교환한다. 학부모 JWT 로는 `/api/drive/*` 전체 403(`rejectParents`). |

### 5.3 앨범 폴더 생성 — 이벤트 상세

| ID | 요구사항 |
|---|---|
| FR-220 | 선생님 이벤트 상세(수정 화면과 신청 현황 화면 공통)의 **"사진 · 영상"** 섹션. 폴더가 없으면 [앨범 폴더 만들기] → 이름 입력(기본값 `YYYY-MM-DD 이벤트명`, 1~100자, 앞뒤 공백 제거, `/ \ : * ? " < > \|` 금지) → 서버가 **루트 폴더 아래**에 Drive 폴더를 만들고 `events.driveFolderId / driveFolderName / driveAccountId / albumCreatedAt` 을 저장한다. 성공 시 섹션이 "폴더 있음" 상태로 바뀐다. |
| FR-221 | 폴더 생성 직후 그 폴더에 **"링크가 있는 모든 사용자 — 보기"**(`permissions.create { type:'anyone', role:'reader' }`)를 설정한다. 앱 갤러리의 썸네일·영상 재생이 Drive 링크를 그대로 쓰기 위해서다. 섹션에 "이 폴더는 링크를 아는 사람이 볼 수 있어요. 링크는 확정된 학부모에게만 보여 줍니다" 를 상시 표시한다. 선생님이 Drive 에서 공유를 끄면 갤러리 썸네일이 깨지므로 [새로고침] 때 `permissions.list` 로 확인해 경고를 띄운다(Q-2). |
| FR-222 | 이벤트당 폴더 **1개**. 생성 후 이름 변경 가능(Drive 이름도 `files.update`). 앱에서 폴더 **삭제 기능은 없다**. Drive 에서 지워지면(files.get 404) 앨범 상태 `missing` — 선생님에게 "Drive 에서 폴더를 찾을 수 없어요 [새 폴더 만들기]" (새로 만들면 기존 미디어 레코드는 `missing` 처리 후 보관). |
| FR-223 | 폴더가 없는 이벤트는 학부모 앨범 목록·이벤트 상세에 앨범이 **보이지 않는다**(섹션 자체 없음). |
| FR-224 | 이벤트 삭제 시 **Drive 폴더와 파일은 지우지 않는다**(앱 DB 의 앨범·미디어·벡터·태그만 CASCADE). 삭제 확인 문구에 "Drive 의 사진은 그대로 남습니다" 를 넣는다. |
| FR-225 | 선생님 섹션에 [Drive 에서 열기](폴더 링크, 새 창)를 둔다. 학부모에게는 폴더 링크를 주지 않는다(파일 단위 링크만, FR-242). |

### 5.4 업로드 — 사진 · 영상

| ID | 요구사항 |
|---|---|
| FR-230 | 업로더는 **선생님 + 확정 학부모**. 파일 다중 선택(한 번에 최대 **30개**), 모바일에서 카메라 직접 촬영·갤러리 선택 모두 지원(`<input type="file" accept="image/*,video/*" multiple>`). |

| FR-232 | **업로드 경로 — 브라우저 → Google Drive 직접 전송(resumable)**. 서버는 파일 바이트를 받지 않는다. ① `POST /api/…/media/uploads` 에 `{name, mimeType, size}` 목록 → 서버가 권한·형식 검사 후 파일마다 Drive **resumable 세션**을 선생님 토큰으로 만들고(`Origin` 헤더 = 앱 주소 → 브라우저 CORS 허용) `event_media(status='uploading')` 행과 **세션 URI** 를 돌려준다. ② 브라우저가 세션 URI 로 `PUT`(8MB 청크, 진행률, 끊기면 `Content-Range: bytes */size` 로 재개). ③ 마지막 청크 응답의 Drive 파일 JSON 을 받아 ④ `POST /api/…/media/:mediaId/complete` 에 `driveFileId`·`takenAt`·(사진이면) **축소본** 을 보낸다. ⑤ 서버가 `files.get` 으로 **부모 폴더 = 앨범 폴더, mime·size 일치** 를 확인하고 `status='ready'` 로 바꾼 뒤 사진이면 얼굴 인덱싱(FR-250)까지 같은 요청에서 처리한다. |
| FR-233 | Drive 파일명은 `{YYYYMMDD}_{업로더표시}_{원본파일명}`. 업로더표시: 선생님 → `선생님`, 학부모 → 그 이벤트에 확정된 첫 자녀 이름(예: `20260905_김하은_IMG_1234.jpg`). 원본명과 업로더는 DB 에 따로 저장한다. 동명 파일은 Drive 가 허용하므로 덮어쓰지 않는다. |
| FR-234 | **축소본**: 브라우저가 `createImageBitmap`/canvas 로 긴 변 1,600px, JPEG 품질 0.85, ≤1MB 로 만든다(EXIF 회전 반영). iOS Safari 는 HEIC 를 파일 선택 시 JPEG 로 넘겨주므로 그대로 동작한다. 브라우저가 디코드하지 못하는 파일(안드로이드 HEIC 등)은 축소본 없이 완료 보고 → `faceStatus='skipped'` → 선생님 [미분석 다시 분석](FR-252)에서 서버가 Drive **썸네일(JPEG, `sz=w1600`)** 을 받아 처리한다. Drive 원본은 HEIC 그대로 보관한다(Q-6). |
| FR-235 | 중단·실패: `uploading` 상태가 **24시간** 지나면 목록에서 제외하고 정리한다(미완료 resumable 세션은 Drive 에 파일을 만들지 않는다). 같은 파일 재시도는 새 세션이다. `complete` 검증 실패(다른 폴더·크기 불일치)는 행을 `deleted` 로 두고 Drive 파일을 휴지통으로 보낸다. |
| FR-236 | **촬영 시각**: 사진은 브라우저에서 EXIF `DateTimeOriginal` 을 읽어 `takenAt` 으로 보낸다. 없으면(영상 포함) 업로드 시각. 갤러리 정렬·날짜 그룹 기준이다. 영상의 `width/height/durationMs` 는 `complete` 뒤 `files.get(videoMediaMetadata)` 로 채운다(Drive 처리 전이면 NULL, [새로고침] 때 재시도). |
| FR-237 | 업로드 중 앱을 나가면 경고(`beforeunload`). 완료 화면: "사진 12장 · 영상 2개 올렸어요. 얼굴 분석 10장 완료 / 2장 분석 안 됨". |
| FR-238 | 선생님 **"업로드 받기"** 토글(`events.albumUploadOpen`, 기본 ON). OFF 면 학부모 업로드 버튼이 "업로드가 마감됐어요" 로 바뀌고 `uploads` API 는 403. 선생님 본인 업로드는 항상 가능. 이벤트 전에도 올릴 수 있다(제한 없음, Q-5). |
| FR-239 | Drive 용량 부족(`storageQuotaExceeded`) → 세션 생성 단계에서 막힌다. 학부모에게 "선생님의 Drive 용량이 부족해요. 선생님께 알려 주세요", 선생님에게는 배너 + 설정의 남은 용량 표시. 선생님 알림(FR-295) 발송. |

### 5.6 얼굴 인덱싱 — 업로드 시 자동, Supabase 저장

### 5.8 매칭 · "우리 아이만" 필터 · 확인

| ID | 요구사항 |
|---|---|
| FR-270 | **매칭 규칙**: `media_faces.descriptor <-> child_face_profiles.descriptor`(유클리드, pgvector `<->`). 미디어 × 학생마다 **최소 거리 d** 를 구해 d ≤ `face_match_threshold`(0.50) → 자동 태그 `source='face'`, 0.50 < d ≤ `face_candidate_threshold`(0.60) → 후보 `source='candidate'`, 그 밖엔 없음. 대상은 **같은 선생님 소속 학생**으로 한정한다. `distance`·`faceId` 를 태그에 남긴다. |
| FR-271 | **우선순위와 보존**: `manual`(선생님) > `parent_confirmed` > `face` > `candidate`. 재매칭은 `face`·`candidate` 만 갱신하고 나머지는 건드리지 않는다. 선생님 태그 해제·학부모 [아니에요] 는 `excluded` 로 남겨 재매칭 때 되살아나지 않게 한다. |
| FR-272 | 학부모 **[우리 아이만]**: 내 연결 자녀 중 하나라도 `face`/`manual`/`parent_confirmed` 태그가 있는 미디어. 그 위에 **"혹시 우리 아이? n장"** 접이식 묶음(`candidate`) — 사진마다 [맞아요](→ `parent_confirmed`) / [아니에요](→ `excluded`, 그 자녀만). 자녀가 둘 이상이면 칩으로 자녀별 필터. |
| FR-273 | 기준 얼굴이 없는 학부모가 [우리 아이만] 을 누르면 "얼굴 사진을 등록하면 우리 아이 사진만 모아 볼 수 있어요 [등록하러 가기]". 수동 태그가 이미 있으면 그 사진들은 보여 준다. |
| FR-274 | **재매칭 트리거**: 사진 인덱싱 완료(그 사진만), 기준 얼굴 등록/삭제(그 학생만), 선생님 [다시 매칭](앨범 전체), 임계값 변경 안내. 재매칭은 멱등이다. |
| FR-275 | 자녀 연결 해제 → 그 학부모의 필터에서 빠진다(태그는 학생 단위라 유지). 학생 삭제 → 프로필·태그 CASCADE. 학부모 계정 삭제 → 그 학부모가 올린 프로필 삭제(FR-263 규칙), 올린 미디어는 남고 `uploaderUserId=NULL`. |

| NFR-5 | **개인정보**: 저장 최소화(벡터·위치만, 얼굴 이미지는 기준 얼굴만 비공개 버킷). 동의 문구(FR-260). 삭제 연쇄(FR-263, 275, 291~293). Drive 폴더의 링크 공유 범위를 선생님에게 상시 고지(FR-221). **실서비스 전 검토 항목**(구현 차단 아님): 생체정보 고지·동의 문구 법적 검토, 다른 아이 얼굴도 분석된다는 고지 범위, 보관 기간. |
| NFR-6 | **비용**: Drive API 무료(사용자당 1,000 req/100초 이내로 설계 — 업로드 1개당 세션 1 + files.get 1), face-api 서버 실행 건당 0, pgvector 는 Supabase 기본 제공, Supabase Storage 는 기준 얼굴(≈1MB × 자녀 수)뿐. |

## 8. 수용 기준 (출시 체크리스트)

- [ ] 선생님이 설정에서 Google 계정을 연결하면 My Drive 에 `RG Manager` 폴더가 생기고, 설정에 이메일·남은 용량이 보인다.
- [ ] 이벤트 상세에서 폴더 이름을 넣고 만들면 `RG Manager` 아래에 그 이름의 폴더가 생기고, 링크 공유(보기)가 켜져 있다. Drive 미연결이면 설정으로 안내된다.
- [ ] 확정 학부모가 사진 5장·영상 1개를 올리면 Drive 폴더에 `YYYYMMDD_자녀이름_원본명` 으로 들어가고, 앱 갤러리에 바로 보인다. 서버 로그에 파일 바이트 수신이 없다.
- [ ] 100MB 영상 업로드 중 네트워크를 끊었다 붙이면 이어서 올라간다.
- [ ] 미확정 학부모는 앨범 목록에 그 이벤트가 없고, URL 직접 접근은 403 안내 화면이다.
- [ ] 선생님이 업로드 받기를 끄면 학부모 FAB 이 비활성, API 는 403, 선생님은 계속 올릴 수 있다.
- [ ] 사진 업로드 완료 응답에 `faceStatus='done'`·`faceCount` 가 오고, `media_faces` 에 얼굴 수만큼 벡터가 저장된다. 축소본 파일은 어디에도 남지 않는다.
- [ ] 학부모가 자녀 얼굴 2장을 등록하면(얼굴 0개·2개 사진은 거절됨) 기존 앨범에서 그 자녀 사진이 "우리 아이만" 에 즉시 나타난다.
- [ ] 학부모 API 응답에 다른 자녀의 태그·얼굴 박스·다른 학부모 이름이 없다(테스트로 고정).
- [ ] 선생님이 수동 태그를 붙인 사진은 [다시 매칭] 뒤에도 유지되고, [아니에요] 한 사진은 다시 후보로 올라오지 않는다.
- [ ] 선생님이 삭제한 사진은 Drive 휴지통에 있고, 앱에서 벡터·태그가 함께 사라진다. 학부모는 남의 사진에 삭제 버튼이 없다.
- [ ] Drive 에서 파일을 지운 뒤 [새로고침] 하면 앱에서 `missing` 처리되어 보이지 않는다.
- [ ] 이벤트를 삭제해도 Drive 폴더·파일은 남는다.
- [ ] 선생님이 Google 권한을 철회하면 배너가 뜨고 업로드는 막히되 앨범 조회는 된다.
- [ ] 순수 함수·컨트롤러 단위 테스트 통과, e2e 스펙 커밋(환경변수 없으면 skip).
